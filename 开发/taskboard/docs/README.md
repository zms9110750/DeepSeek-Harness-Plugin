## 四个最容易搞混的地方

### ① 「行为」有两个意思

```
模板的 behavior   这一条要用户做什么     → 模板和章节.md
章节的 action     这一章用什么控件       → 交互行为.md
```

源文件里一个叫 `behavior:` 一个叫 `type:`，但中文都能叫「行为」。

### ② 「需求授权」和「需要信息」不是一回事

```
需要授权 = 用户拍板，AI 无权改     → 设计类 / 记录类初始状态
需要信息 = AI 去查，用户不用动     → 工作卡住但 AI 自己能解
```

判据不是「听起来像什么」，而是：**这件事 AI 能不能自己搞定。**

详见 [模板分类和状态转移.md](./模板分类和状态转移.md) 第三节。

### ③ 「阻碍」是事项，「约束」是关系

```
阻碍（RB）    一条事项，一出现父工作变「需要授权」
约束（links） 一条边，跨树指向别的卡，不产生新事项
```

详见 [关系.md](./关系.md)。

### ④ 父子不是关系的一种

父子管层级（影响状态推导），关系管牵连（不参与推导）。

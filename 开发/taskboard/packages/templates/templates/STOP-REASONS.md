# 停止原因（stop reasons）

> H1–H8 原本是 8 个独立模板，混在"做什么"的模板列表里。
> 它们和 A–F 不是一个维度：A–F 回答**做什么**，H 回答**为什么停**。
>
> 现在降级为**理由词表**：阻碍模板（`B.yml`）的一个字段，或者状态变更时的一句话。
> 不再是一等模板。

## 为什么合并

原来看起来像"8 种不同的活"，其实是同一个动作（停下来）的 8 个理由。
把它们做成 8 个模板的代价：

- 模板下拉里一半是"为什么停"，用户建"做什么"时被干扰
- 每加一种停止理由就要加一个模板文件
- 理由不能组合（"缺权限" + "代价过大"同时成立时只能选一个）

## 词表

分为两类，对应九态里的「需要授权」和「需要信息」：

### 需要授权（要用户做决定才能继续）

| id | 名称 | 什么情况 |
| --- | --- | --- |
| `cost` | 代价过大 | 方案能走，但钱/时间/风险超出预期 |
| `scope` | 用户转移话题 | 原目标还悬着，用户去关心别的了 |
| `flaw` | 方案缺陷过大 | 现有方案有根本问题，要么换路要么放弃 |
| `resource` | 资源被占用 | 机器/端口/名额被别的东西占着 |
| `permission` | 缺权限 / 环境不对 | 被权限或环境挡住，要先改变操作环境 |

### 需要信息（缺信息才能继续）

| id | 名称 | 什么情况 |
| --- | --- | --- |
| `info` | 缺用户信息 | 只有用户知道的事，问不到就做不下去 |
| `research` | 需要先调研 | 自己不知道，但可以查 |
| `children` | 子任务未回收 | 派出去的事还没回来，回收完才能继续 |

## 怎么用

阻碍模板里的字段：

```yaml
- type: dropdown
  id: reason
  attributes:
    label: 停下来的原因
    options: [代价过大, 缺用户信息, 需要先调研, ...]
```

或者状态变更时的一句话：`task_state(id, '需要授权', note='代价过大：要买 X，$200/月')`。

## 与旧数据的兼容

老的 `type: H1`–`H8` 仍然能读，按 `TYPE_TO_KIND` 推成 `record`。
新数据不再写 `H*`，改用阻碍模板 + `reason` 字段。

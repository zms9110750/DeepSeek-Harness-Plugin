## 全局紧急恢复（工具链被插件搞坏时）

如果某个插件让所有工具调用报错（例如 `session.snapshotEvents is not a function`），用文本编辑器打开：

```
C:\Users\16229\.dsh\profiles\desktop\cordis.patch.yml
```

在末尾追加（顶格，两空格缩进）：

```yaml
- id: <出问题的 entry id，如 gate-switch11>
  disabled: true
```

保存后 HMR 会摘掉它；不行就完全退出应用再开。恢复后把这条删掉，再用 `plugin_manager` 正常卸载。

备份：该文件每次改动前留了 `.bak-gate`。

## 权限注入的原理与风险

`gate-switch11` 用 `inject: ['tools','sessionProjections','permissionPresets']` 等权限服务就位后，直接改它实例上的 `presets` 表（官方没有注册 API，只有固定的 `registerAuto`），再 `emit('permission-presets/catalog-changed')` 让客户端重拉目录。

**风险**：这依赖服务实例的内部字段名 `presets`。DSH 升级后若改名或改为私有，插件会在 `apply` 阶段抛错——表现为该 entry `failed`，工具不受影响（守卫没注册上），但菜单里不会有「工具全关」。修法：检查 `dsh-permission-presets` 的类字段，或改用同名包覆盖。

**守卫必须 fail-open**：`tools.guard` 对每次调用都执行，抛异常会把整条工具链带崩（`gate-switch8` 就是这么把工具锁死的）。11.0.0 用 try/catch 兜底。

## session-fork-bridge（接管 fork 通路）

## plan-tree 步骤 1：自动归档（0.7.0）

**装的是什么**：`@local/plan-tree` 0.7.0，源码 `开发/plan-tree`。派发子节点后，子停稳时由插件自己把结算写进父日志，不再依赖父手动调用 `plan_file`。子被要求在收尾时回六行：`verdict` + 五项（conclusion/evidence/artifacts/pitfalls/where）。

**行为边界**：
- 六行解析成功 → 自动追加一条 `plugin:plan-tree/node`（`op:'file'`），节点状态随之变成 success/reject/shelved，计数同步。
- 六行缺行或 `verdict` 不在 success/reject/shelved 里 → **不写任何事件**，节点保持 open，回传消息里带一句「未自动归档，需要父手工 plan_file」。
- 回传消息本身不变：仍是 `user/message` + `source.kind='subagent-settled'`，界面渲染成折叠的「子任务状态更新」。
- 不新增事件类型，不走 `session.append`，不碰 `system/message`。

**失败表现**：
- 写事件失败（`appendNode` 抛错）→ 被吞掉，`autoFiled=false`，回传里提示未归档；节点留 open，可手工 `plan_file`。
- 解析器误判（子多写了别的行）→ 只要六个键都在且 verdict 合法就会归档；内容里混进多余文字不影响键识别。
- 插件整体坏掉 → `plugin_manager list_plugins` 里 `include:plan-tree` 不是 active。

**怎么撤**：
1. `plugin_manager remove_bundle @local/plan-tree`
2. 会话里已经写下的 `plugin:plan-tree/node` 记录是 ignorable 的，**不删也能正常读写会话**；要彻底清掉，用 `探针/repair-session-log.mjs` 或手改日志把带 `plan-tree` 的记录去掉——不做也安全。
3. 想退回手动归档：把版本换回 0.6.0（`git log`/备份目录里有源码），或在 `whenIdle` 里把 `appendNode(agent.session,'file',…)` 那段删掉。

## plan-tree 步骤 2：计划落成文件（0.8.0）

**装的是什么**：`plan_write` 工具。参数：标题、目的、判据、去处、正文、（可选）类型/层/目录。把一份计划写成一个 `.md` 文件，默认落在 `<会话 cwd>/计划/` 下，文件名由标题生成（保留中文，去掉 `\ / : * ? " < > |` 和空白）。

**行为边界**：
- **不写任何会话事件、不进树**。树上只有"派发过的"节点，起草不算。
- 不做评审、不弹框。要让用户看到，由父再调 `present`（内置工具），把文件列成卡片。
- 文件覆盖写：同名标题会覆盖上一版。要保留多版，标题里带版本号（`B-02 真分叉 v2`）。
- 目录不存在会创建。

**失败表现**：
- 标题为空 → 用随机 8 位作文件名。
- 目录不可写 → 工具调用报错（`plan_write` 抛错），不会静默成功。
- 写错位置：传 `dir` 指定。

**怎么撤**：
1. `plugin_manager remove_bundle @local/plan-tree`
2. 它写出的计划文件是普通 `.md`，删不删由你（不影响任何会话）。
3. 只想去掉这个工具、保留其它：把 `name: 'plan_write'` 那段 `ctx.tools.register(...)` 删掉，版本号 +1 重装。

**测试记录（步骤 2）**：

## plan-tree 步骤 4：采纳即分叉（0.9.0）

**装的是什么**：新增 `plan_adopt(plan)`；`plan_dispatch` 的签名改成 `plan_dispatch(plan, reason, [workspace])`——不再自己带 topic/goal/判据，全部从被采纳的计划里取。

**行为边界**：
- `plan_write` 现在返回 `{ id, path }`（id 形如 `p1`），并在日志里记一条 `op:'plan'`。计划进 `state.plans`，**不进树**（树只渲染派发过的节点）。
- `plan_adopt` 记 `op:'adopt'`，把计划标成已采纳。重复采纳是幂等的（不重复写事件）。
- `plan_dispatch` 先查计划：不存在 → 报错；存在但未采纳 → 报错 `has not been adopted`。**两道检查都在建子会话之前**，不会留下半截会话。
- 采纳记录就是种子边界之前最后一条事件，所以"采纳即分叉点"成立。

**失败表现**：
- `no plan "p1"` → 没写就派发。
- `plan "p1" has not been adopted` → 忘了 `plan_adopt`。
- 老调用方式（直接传 topic/layer）会因缺 `plan` 参数被 schema 拒。

**怎么撤**：
1. `plugin_manager remove_bundle @local/plan-tree`；
2. 只想恢复旧签名：把 `plan_dispatch` 的 `parameters` 换回 topic/goal/done_when/where_to_learn/type/layer，并把 execute 开头那段"查计划"删掉；`plan_adopt` 可留着不用；
3. 已写的 `op:'plan'`/`op:'adopt'` 记录是 ignorable 的，不影响会话读写。

**测试记录（步骤 4）**：
- `plan_write(标题=采纳门禁自检, layer=D, dir=探针/adopt-test)` → 返回 `p1`，日志 seq 5877 `op:'plan'`；
- `plan_dispatch(plan=p1)` → 被拒：`plan "p1" has not been adopted`；
- `plan_adopt(p1)` → 通过，seq 5888 `op:'adopt'`；
- `plan_dispatch(plan=p1, reason=…)` → 通过，建出 n7；
- 子会话日志（5907 条事件）里同时含 `plan p1`、`adopt p1`、`dispatch n7`，说明种子边界在采纳之后，**采纳即分叉点成立**。

## plan-tree 步骤 5：格式来自可手改的模板（0.10.0）

**装的是什么**：`plan_write` 不再自己拼一份通用 md，而是读一份**模板文件**，按其中的层与小节渲染骨架。模板就是 `计划/提案格式.md` 这种形状：`## 层名` 开头，下面 `- 小节名` 顶格列出；缩进的 `-` 是说明文字，会被忽略。

**行为边界**：
- 默认模板 `<会话 cwd>/计划/提案格式.md`，可用 `template` 参数指定别的文件。
- 层用序号比较深浅，**插件不认识任何固定层名**（A/B/C/D 只是默认模板里恰好这么叫）。
- `layer` 参数写层名的首字母（`B`）或全名（`B系列-设计`）都行。
- **小节可以留空**：headings 一律渲染，内容为空也合法；用户本来就要过目和改。
- 找不到模板文件 → 报错并给出确切路径；模板里没有 `##` → 报错。
- 计划记录里存 `layer`（层名）、`layerIndex`（序号）、`templatePath`。

**失败表现**：
- `no template at …` → 模板文件不存在。
- `no layer "X" in …; available: …` → 层名不在模板里，报错会列出可选层。
- `this plan has no layer index` → 用了旧版写的计划去派发，重写一份即可。

**怎么撤**：
1. `plugin_manager remove_bundle @local/plan-tree`；
2. 插件不写模板文件，删它不影响任何东西；`计划/提案格式.md` 是你自己的文件；
3. 想回到 0.9.0 的通用 md 渲染：把 `renderPlan(args, layer)` 换回 `renderPlan(args)` 的旧实现。

**测试记录（步骤 5）**：
- `plan_write(title=模板驱动自检, layer=B, dir=探针/template-test)` → 文件 18 行，出现 `## B系列-设计` 与四个小节（主要目标/次要目标/约束·许可·缺点/工具），每个小节下只有一个空 `-`。
- 层名解析：传 `B` 命中 `B系列-设计`，文件头 `- 层：B系列-设计`。

## plan-tree 模板语法修订（0.11.0）

**改了什么**：模板的分节语法从"顶格 `-` 当小节"改成 markdown 原生层级——`##` 是层，`###`～`######` 是层里的小节，`-` 开头的都是说明文字（原来那套"缩进减号"不再参与解析）。`templates/提案格式.md` 已按新语法重写。

**行为边界**：
- 层的顺序 = 文件里 `##` 的出现顺序，第一个 `##` 最浅。
- 小节顺序 = 该层内 `###` 的出现顺序。
- 只有 `##` 没有 `###` 的层，渲染出来只有一个光标题（合法，但闸门仍按层序工作）。
- 旧语法模板（顶格 `-` 当小节）在新版里会被忽略小节，只剩层标题。

**怎么撤**：把 `parseTemplate` 里的 `/#{2,6}/` 改回 `/- /` 那版即可；模板文件也要改回去。插件本身不用卸载。

**测试记录**：
- `plan_write(layer=A)` → 16 行，`## A系列-问题` 下面三个 `### 痛点/验收 / 适用性 / 先例` 全部渲染，内容为空。

## plan-tree 0.12.0：小节问题随骨架带出

**改了什么**：模板里每个 `###` 小节下的 `-` 说明，不再被丢弃，而是原样带进生成的计划文件——按 `### 标题 → 要回答：→ 逐条问题 → 回答：` 的顺序渲染。写计划的人（模型）先看见要回答什么，再决定填不填；留空合法，由用户看文件时决定是否打回。

**行为边界**：
- `-` 行归属最近一个 `###` 小节；层标题（`##`）之下的 `-` 行不属于任何小节，会被丢弃。
- 没有 `-` 说明的小节，只渲染 `### 标题` + `回答：`。
- 解析结构从 `sections: string[]` 变成 `sections: { title, prompts: string[] }[]`——任何读 `layer.sections` 的代码都要跟着改。

**怎么撤**：把 `parseTemplate` 里收集 `prompts` 的两行删掉、`renderPlan` 里 `要回答：/回答：` 那段删掉，即回到 0.11.0 的"只出标题"。

**测试记录**：
- `plan_write(layer=A)` → 33 行，三个小节各自带出模板里的问题，`回答：` 为空；未写内容也正常落盘。

## plan-tree 0.14.0：否决草案 + 按钮的两条命令

**装的是什么**：新增 `plan_reject(plan)` 工具（草案否决，不计数）；新增两条命令 `/plan-adopt <路径>`、`/plan-reject <路径>`，按文件路径找计划——这是留给产物卡片按钮调用的入口。

### 0.17.1：三处没按卸载规范写的地方（已修）

**框架这一侧是对的**：`tools.register()`、`tools.guard()`、`commands.register()` 都走 `ScopedLayers.effect(ctx, …)`，内部就是 `ctx.effect(...)`，disposer 挂在**调用方 fiber** 上；`ctx.provide()` 在 cordis 里同样是 `fiber.effect`。所以"插件关掉之后注册残留"不会发生——这是框架保证的。

**但我有三处自己写的状态会活过 fiber**：

1. `lock` 的 `unlocked` 是模块级 `Set`：卸载后还活着，重新启用会悄悄继承上一次的"已放开"。→ 挪进 `apply()`。
2. `dispatch` 的回传续体是挂在子会话上的 `whenIdle().then(...)`：插件卸载之后它还会醒过来，往日志里写记录。→ 加一个 `disposed` 闸门（`ctx.effect(() => () => { disposed = true })`），醒来先看它。
3. 客户端 `runtime` 在卸载后仍指向死 ctx。→ 卸载时置空，页面宁可报"没有 remote"也不对死 ctx 操作。

**由此立两条规矩**（写进这里是防止再犯）：
- 任何异步续体（`whenIdle`、`setTimeout`、`Promise.then`）都必须有一个 disposed 闸门；
- 任何会话级活状态（"已放开"、缓存）都必须放在 `apply()` 里，不能放模块顶层。

**上次"关了就不对"的真实原因不在清理**：一是 `dsh-client-modules` 把包元数据（含有没有 `dsh.client`）按 specifier 缓存到重启；二是 `set_bundle false` 会把包从 `bundles` 摘掉却留下 `dependencies` 行，随后 `remove_bundle` 就报 `bundle-in-use`。这两条都是管理器/模块系统的记账，跟 disposer 无关。

### 清理修复（2.0.0 / 12.0.0）

两个插件原先都是**裸赋值**，卸载时 Cordis 不知道要还原：

- `session-fork-bridge`：`controller.fork = 包装函数`，卸载后包装仍在，且绑定已销毁的上下文；
- `gate-switch11`：直接清空并重排 `permissionPresets.presets`，卸载后表里永久多一项。

- presets：卸载时清空并**按卸载前的顺序**写回，再发 `catalog-changed` 让界面重拉。

`plan-lock`（`@local/plan-tree2/lock`）用了 `ctx.commands.register` 但 `inject` 里没有 `commands`，Cordis 直接拒绝激活（`cannot get property "commands" without inject`），导致整次重组合报 `1 entry did not activate`。已在 `开发/plan-tree/src/lock.js` 的 inject 里补上 `commands`，现为 active。
### 12.0.1：清理只清自己（presets 还原再收一格）

12.0.0 的还原是"清空整表 + 按卸载前的快照写回"。它修好了"卸载后表里永久多一项"，但多了一个副作用：**在我们挂载期间别的插件注册/删掉的档位，会被这次还原一起抹掉**——那不是清理自己，是回滚别人的工作。

现在只动自己那个键：

```js
ctx.effect(() => {
  const had = Object.hasOwn(table, PRESET);
  const previous = had ? table[PRESET] : undefined;
  table[PRESET] = { … };
  ctx.emit('permission-presets/catalog-changed');
  return () => {
    if (had) table[PRESET] = previous; else delete table[PRESET];
    ctx.emit('permission-presets/catalog-changed');
  };
});
```

测试（`探针\gate-switch11.test.mjs`，对 11 和 12 各跑一遍，共 10 条）：注入后别人的档位与顺序不变；卸载后 `no-tools` 消失且再发一次 `catalog-changed`；**卸载不抹掉别人在我们挂载期间加的档位**（这条 12.0.0 会挂）；卸载再启用不出错；守卫对 `no-tools` 拒一切、读不到投影时放行。

**操作规矩：先切档，再禁用。** 禁用之后 `no-tools` 从枚举里消失，而会话投影里存着的 `preset: 'no-tools'` 还在——那是个悬空的档位名。守卫随之消失，工具会恢复（失败向安全：宁可放开，也不永久锁死），但"我明明锁着"的错觉就是这么来的。

## 2026-10-21 18:05 · `@local/secrets-llm` 0.1.0（新包，只装 dev）

**要解决**：模型密钥不许进上下文、不许放环境变量。配置里只留**引用**：读哪个文件、取哪一节；密钥、端点、模型名都从 C# 项目的 user-secrets 文件在**每次启动时**读出来。

**为什么不是"配一个 `apiKeyEnv` 就完事"**：pi-ai 的路由字段里，只有 `apiKeyEnv` 接受 credential-ref（`baseURL`、`models` 是普通字符串）。也就是说 url 和 model 在 stock 配置里**根本无法变成引用**。所以这个插件自己把文件读出来，再用 `ctx.plugin()` 挂一个 pi-ai，把三条值一次喂进去——profile 里就真的一个都不写。

**为什么能提供 `credentials`**：base 装配了 `dsh-credentials-local`，但 **headless 把它整行禁用了**（"One-shot jobs use launch-time credentials instead of the interactive store"）。这个座位在 CLI profile 里是空的，插件坐上去正好，`resolve` 按引用给值，`describe` 只给事实。

**关键实现点**（三个都是踩过的坑）：

1. **文件带 BOM**。`JSON.parse` 直接抛 `Unexpected token '﻿'`。读入后先 `replace(/^\uFEFF/, '')`。
2. **profile 里 import 不到 dsh 包**。profile 的 `node_modules` 只有它自己的插件，宿主在应用里；裸 `import('@deepseek-ai/dsh-llm-pi-ai')` 必失败。做法：用 `createRequire(process.argv[1]).resolve(...)` 从宿主入口往上找，再 `import(pathToFileURL(...))`；还留了 `process.resourcesPath/app.asar/dsh` 兜底。实测解析到 `…\dsh\node_modules\@deepseek-ai\dsh-llm-pi-ai\lib\index.js`。
3. **profile 补丁里新增一行必须写成 `insert:`**。裸 `- id: secrets-llm\n name: ...` 只用于覆盖已有行，新 id 会被**静默忽略**——表现为插件根本没 apply（当时还以为是 import 失败）。

**验证**：`探针\secrets-llm.test.mjs` 10 条全过（含"密钥不进日志"、"describe 不含值"、"已有 store 时拒绝"、"非 ASCII 节名退化成 `LLM_` 前缀"）。端到端 headless：`node bin.js --profile dev "只回答两个字：通了"` → 模型真的回「通了」，路由 `cc-goat`、端点 `https://api.commandcode.ai/provider/v1`、模型 `deepseek/deepseek-v4-flash` 全来自文件。

**装的形态**：dev 里三个包都用 `link:`（改完即生效）；`file:` 会拷贝，改代码后 `pnpm` 判"Already up to date"不刷新——踩过一次。

**回滚**：删 dev `package.json` 里 `@local/secrets-llm` 依赖 + 补丁里 `insert` 那块，恢复 `llm-pi-ai` 行，`pnpm install`。桌面 profile 未受影响。

# ⑪ dsh-command —— dsh 斜杠命令适配

> 把核心能力包成 `/task-*`。只做适配，不做事。

**状态：草稿。接口与规则待用户设计并同意。**

---

## 一、它是什么

每个 handler 只做三件事：

```
① 把文本行切成参数
② 调核心
③ 把结果渲染成 dsh 的 { kind, text }
```

**这一层没有 if。**

---

## 二、边界

### 做

- 注册 `/task-*` 斜杠命令
- 把 `rawInput` 切成参数
- actor 的来源（dsh 的 agent → 我们的 actor）
- 把结果转成 dsh 期望的返回形状

### 不做

- 任何业务判断 → ⑧ core
- 命令的实现 → 核心的 public 方法就是实现

---

## 三、为什么独立成包（用户已确认）

**用户是外部对端**，命令名是肌肉记忆。

有人可能想换一套命令集 —— 那就该能关掉换一个。

补一条：**命令名一旦发布就不能随便改。**

---

## 四、上下游

- **上游**：⑧ core + 宿主的 `commands` 服务
- **下游**：无

**不依赖** ⑨ —— 工具和命令是两套消费者，都直连核心。

---

## 五、使用处（大概）

- 用户在对话里敲 `/task-state RB-01 成功`
- 命令的返回值渲染成一行文本

---

## 六、待用户设计并同意

- 命令清单与命名（`/task-state` 还是 `/tasks state`）
- 参数怎么切（文本行 / JSON）
- 返回什么形状
- 哪些命令只给用户（采纳 / 打回）
- `recordInput` 设什么（旧版全设 false，避免淹会话日志）

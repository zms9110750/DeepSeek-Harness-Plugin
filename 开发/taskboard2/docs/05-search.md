# ⑤ search —— 搜索

> 按条件查事项、按关系反查、按树取后代。**只读。**

**状态：草稿。接口与规则待用户设计并同意。**

---

## 一、它是什么

旧版没有查询能力，只有「全量读回来自己筛」。这一层把「筛」收拢成一份可序列化的**条件**，宿主和界面传同一份。

---

## 二、边界

### 做

- 按条件查（状态 / 分类 / 模板 / 父 / 领取者 / 组 / 归档 / 关键词）
- 按关系反查（谁依赖我、谁取代我）
- 按标签、按标记查
- 按树取子树
- 分页

### 不做

- 写盘 → ① store
- 判断可不可以领 → ⑧ core（那要查依赖、父、领取者）
- 状态组含义 → 条件里的组是字符串，交给调用方解释

### 关键约束（用户已确认）

- **单向：只读。** 不改任何东西、不写盘、不触发级联。
- **条件可序列化。** 宿主和浏览器传同一份，避免两套筛法必然漂。
- **接口不承诺有索引。** 允许实现挂索引，但换一个暴力实现也合法。

---

## 三、上下游

- **上游**：① store（读）
- **下游**：⑧ core · ⑨ ai-tool（可复用）
- 它**不认识** ③ types —— 条件里的状态、分类、模板都是字符串，不是对象。

---

## 四、使用处（大概）

- 面板列卡片时传条件给它，而不是自己筛
- AI 工具 `task_list` 传条件给它
- 核心做领取检查时问它「谁在等我」

---

## 五、待用户设计并同意

- 条件的字段与形状
- 关键词搜索范围：只标题 / 标题+正文首行 / 全文
- 要不要支持排序
- 归档的语义：「包含归档」还是「只查归档」
- 分页的形状

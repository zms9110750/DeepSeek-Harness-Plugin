# ⑧ core —— 核心

> 唯一编排入口。事务边界、调用顺序、对外门面。

**状态：草稿。接口与规则待用户设计并同意。**

---

## 一、它是什么

别的模块只做自己的判断，核心只做「按顺序问、按顺序写」。

```
读 → 问策略 → 写 → 问级联 → 再写
```

---

## 二、边界

### 做

- 事务边界（一次改状态可能改多条，必须原子）
- 调用顺序（先判定再写、先转移依赖再判死刑）
- 对外门面（读 / 写 / 规则查询）

### 不做

- 状态能不能转 → ③ types
- 这个分类允不允许 → ③ types
- 派发允不允许 → ③ types
- 存到哪 → ① store
- 级联谁 → ④ relation（算计划）

### 关键立场（用户已确认）

**整个系统强依赖、不可解耦的东西在核心包里。**

**核心里的 if 形式的业务规则都是错的**（`if (kind === ...)`、`if (status === ...)` 都该在 ③）。

---

## 三、上下游

- **上游**：0–1 层全部（① store ② action ③ types ④ relation ⑤ search ⑥ workgroup ⑦ taskcard）
- **下游**：⑨ ai-tool · ⑩ ui · ⑪ dsh-command

**不依赖** ⑨⑩⑪ —— 方向是它们依赖核心。

---

## 四、使用处（大概）

- AI 工具调它
- 斜杠命令调它
- UI 直接调它（浏览器是自有终端，不需要中间桥接层）

---

## 五、关于「接口面」

**没有独立的「命令包」。** 核心的 public 方法就是接口面。

浏览器可破坏性更新，它自己就能桥接；模型和用户的协议是固定的，所以只有它们需要桥接（⑨⑪）。

# ⑩ ui —— UI 提供层 + 两个入口

> 一个包，三个模块：提供层 + 工作区入口 + 抽屉入口。**画面只有一份。**

**状态：草稿。接口与规则待用户设计并同意。**

---

## 一、它是什么

```
提供层  provider          —— 画面本身 + 数据通道 + 状态（重资产）
入口 A  entry-workspace   —— 工作区页签（右侧栏）
入口 B  entry-drawer      —— 输入框旁抽屉
```

两个入口都是提供层的**薄壳**，各自只决定「挂在哪、多大、什么时候显示」。

---

## 二、边界

### 做

- 画面（列表 / 科技树 / 详情 / 新建）
- 数据通道
- 入口开关配置
- 浏览器直启的宿主页（待定）

### 不做

- 业务判断 → ⑧ core
- 状态词表 → ③ types（不重复定义）
- 路径 → ① store（不写死）

### 关键立场（用户已确认）

**一个提供层，两个入口。**

- 如果分成三个包，单独的提供层不起作用 —— **提供层才是重资产**
- 把抽屉单独拆一个包也没用

**为什么这是「单独打开没用」的典型**：两个入口单独存在都没有画面可挂，提供层单独存在没有挂载点。

**宿主侧不提供任何服务** —— 画面在浏览器里跑，宿主侧只承载入口开关。

---

## 三、上下游

- **上游**：⑧ core（数据与动作）
- **下游**：无

> 客户端侧还要 dsh 的槽位、`remote`、配置表单等 —— 那是**客户端 inject**，不是宿主侧 `inject`，两者不要混。

---

## 四、使用处（大概）

- 用户在右侧栏看任务列表
- 用户在输入框旁打开抽屉
- 数据从核心来、动作回核心去

---

## 五、待用户设计并同意

- 技术栈（可换的前提是提供层不绑框架）
- 客户端产物怎么产出（手写单文件 / 打包器）
- 两个入口的挂载点
- 画面有哪些视图
- 是否需要浏览器直启（独立 HTML + http）
- 主题与颜色 token
- 客户端侧 inject 需要哪些服务

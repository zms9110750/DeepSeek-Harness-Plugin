# ⑨ ai-tool —— 给 AI 的工具

> 只翻译，不判断。

**状态：草稿。接口与规则待用户设计并同意。**

---

## 一、它是什么

每个工具做三件事：

```
按 schema 收参数 → 调核心 → 把结果渲染成文字
```

**不许有业务判断。**

---

## 二、边界

### 做

- 工具的注册
- 参数 schema
- 结果渲染成文字
- 系统提示（从同一份定义生成，不手写）

### 不做

- 业务判断 → ⑧ core 及以下
- 身份判定 → actor 由调用现场给

---

## 三、为什么独立成包（用户已确认）

**模型是外部对端**，工具调用的协议与粒度是它要的。

**有人可能觉得工具实现不好** —— 那就该能关掉换一个。这是「必须关掉才能替换」的替换，不是注册扩展。

补一条：**工具名与 schema 一旦发布就不能随便改** —— 那是模型在用的东西。包的可替换性不等于名字可漂移。

---

## 四、上下游

- **上游**：⑧ core + 宿主的 `tools` 服务
- **下游**：无

**不调** ⑪ —— 工具不是命令的包装，两者都是核心的调用方。

---

## 五、使用处（大概）

- 模型在对话中调用工具操作任务
- 系统提示里的工具清单与规则从注册表生成

---

## 六、待用户设计并同意

- 工具清单（多少个、叫什么、合并哪些）
- 每个工具的参数 schema
- 结果渲染成什么样的文字
- 系统提示包含哪些内容、由哪些来源拼成
- 是否复用宿主的 `tools` 服务

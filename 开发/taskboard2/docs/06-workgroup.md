# ⑥ workgroup —— 工作组

> 一个工作组 = 一件事 / 一个项目。**容器不关心里面是什么。**

**状态：草稿。接口与规则待用户设计并同意。**

---

## 一、它是什么

三样独立语义：

- **组** —— id / 名字 / 创建时间
- **成员** —— 哪些事项属于它
- **归档** —— 对**组**归档，不是对单条事项
- **当前组** —— 会话级指针，不是全局偏好

---

## 二、边界

### 做

- 组的增删改查
- 成员管理
- 归档（整组）
- 删除（墓碑真正实现在这里，不外泄）
- 当前组（按会话）

### 不做

- 存储的具体格式 → ① store
- 编号 `g-N` 的算法 → ③ types
- 任务卡里面有什么 → **不关心**
- 层级（子工作空间） → 未定

### 关键立场（用户已确认）

**容器不关心内容。** 成员关系存这里，任务卡上不带组 —— 读卡要带组是读的时候 join，不写进卡。

> **理由（用户原话）**：之前的实现就是没有工作组的时候做的。纳入工作组，只是把任务卡放在工作组里面而已，然后储存工作组。这个容器也不关心这里面是什么。

**为什么独立成包**：它是一个可替换的实现领域 —— 换一种容器实现有意义。而且「子工作空间」这种事可能放在卡上也可能放在组上，现在还没实现，独立出来留出余地。

---

## 三、上下游

- **上游**：① store · ③ types（`g-N` 编号）
- **下游**：⑧ core
- 它**不认识** ⑦ taskcard。

---

## 四、使用处（大概）

- 面板按组列事项
- AI 工具列出组、建组、加成员
- 「当前组」跟随会话：A 会话设了，B 会话不受影响

---

## 五、待用户设计并同意

- 「不能迁移」到底是什么语义（硬禁 / 允许但留痕）
- 删组时成员怎么办（拒绝删非空组 / 要求先迁移 / 级联取消）
- 要不要允许多组（一个事项属多个组）
- 当前组没有时列什么
- 归档后组内事项还能不能被读到
- 子工作空间：放在卡上还是组上

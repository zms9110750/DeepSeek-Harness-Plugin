# 树上下文库 · 探针（日志一张表 + 每个会话一张视图）

目标：**不知情的人打开这个库，就知道这是多个会话的归档。**

他看到的东西：

```
表
  tasks     元数据：任务、标题、父、fork_at、会话、视图名
  events    所有会话的日志（内部存法，一行对一行）

视图
  v_archive 目录：一行一个会话，带一句人话
  s_<会话>   每个会话一张，查它就是查这个会话拼好的完整日志
  v_log     所有会话拼好的日志（程序用，带 task_id）
  v_event   人看的：seq + 事件类型 + 前 200 字
```

## 每分叉一个会话，就多一张视图

视图名 `s_<任务 id>`，定义里第一行就是人话注释：

```sql
CREATE VIEW "s_session_f4dcb221_…" AS
  -- 会话 session-f4dcb221-…，从任务 session-801046dd-… 的第 31 条之后接上（前 31 行在父任务里）
  WITH RECURSIVE up(...) AS (...)
  SELECT e.seq, e.line ...
```

所以打开 DB 浏览视图定义的人，直接能看到"这张视图是哪个会话、从哪儿分出来的"。

## 归档目录

```sql
SELECT * FROM v_archive;
```

```
task                                   | 视图                        | 自己存的/拼起来 | 说明
session-801046dd-…                      | s_session_801046dd_…        | 42 / 42        | 根会话（没有从别处继承）
session-f4dcb221-…                      | s_session_f4dcb221_…        | 24 / 55        | 从任务 session-801046dd-… 的第 31 条之后接上（前 31 行在父任务里）
```

## 查一个会话

```sql
SELECT seq, line FROM s_session_f4dcb221_0d08_40cd_86d6_4eb8f83a065a ORDER BY seq;
```

拿到的就是 55 条完整日志，和原始 jsonl 逐行一致（`store.cjs verify` 验过）。

## 存储规则

每个会话在 `events` 里只存自己新增的行（`seq >= fork_at`）；前面的前缀属于父会话，不复制。拼的工作在视图里。

## 用法

```powershell
cd X:\temp\dsh\探针\sqlite-store
node store.cjs init
node store.cjs import <session-id|路径> [--task ID] [--plan ID]
node store.cjs import-current
node store.cjs archive            # 目录（人话）
node store.cjs tree               # 树形
node store.cjs log <task-id>      # 查某个会话的视图
node store.cjs verify <task-id>
node store.cjs stats
node show-views.cjs               # 看所有视图定义
```

看图：`node X:\temp\dsh\探针\db-view.cjs X:\temp\dsh\探针\sqlite-store\tasks.db` → `tasks.html`。

# 插件配置与二级菜单 · 机制笔记

写这份的原因：配置和菜单是**两套独立机制**，很容易以为「有 Config 就有配置界面」。
我在这上面绕了很久，记下来免得以后重踩。

---

## 一句话

- **配置**：宿主（Node）的事。`Config` schema + patch 的 `config` 字段。
- **界面**：浏览器的事。`ctx.slots.register` 注册一个 React 组件。

**两者没有自动联系。** 有 `Config` 不会自动出现配置页；配置页也不会自动读你的 Config。

---

## 一、配置怎么写进包

### 三层 patch 叠加，后者整块覆盖前者

```
① 空 entry 列表 []
      ↓ 按 dsh.profile.bundles 顺序，逐个应用 bundle 的 patch
② @deepseek-ai/dsh-base 的 patch
③ @local/taskboard 的 patch          ← 包内的 cordis.patch.yml
      ↓ 应用 profile 自己的 patch
④ profiles/<name>/cordis.patch.yml    ← 用户在界面上改的值写这里
      ↓ 应用启动参数
⑤ --patch 文件 / 命令行 flag
```

源码位置：`@deepseek-ai/dsh-app-boot/lib/index.js`，`applyEntryPatches()`。
注释原文：

> the tree is composed by applying each bundle's patch lists in
> `dsh.profile.bundles` order over an empty entry list, **then the profile's own
> patches, then any launcher layers**

### 包内的 patch 长这样

`X:\temp\dsh\开发\taskboard\cordis.patch.yml`：

```yaml
- insert:
    - id: taskboard-ui
      name: '@local/taskboard-ui'
      config:
        drawer: true
        sidebar: true
```

加载器按 **`id`** 找行，把 `config` 挂上去。

### ⚠️ 覆盖是整块替换，不是深合并

```js
for (const [key, value] of Object.entries(overrides)) {
  if (key === 'id') continue;
  target[key] = value;
}
```

`config` 是**一个整体值**。profile 里写：

```yaml
- id: taskboard-ui
  config:
    drawer: false
```

`sidebar` 就**丢了**（整块 config 被替换），之后靠 schema 的 `.default(true)` 兜底。

**所以 profile patch 里 `config` 要写全字段。**

### 用户在界面上改开关，写到哪里

实测（tbtest profile 点「抽屉」开关后）：

`profiles/tbtest/cordis.patch.yml` 末尾多出：

```yaml
- id: taskboard-ui
  name: "@local/taskboard-ui"
  config:
    drawer: false
    sidebar: true
```

注意：**它写的是完整 config**，不是只写改动的那个字段。所以界面写不会踩上面那个坑。

## 二、Config schema 的硬要求：`.volatile()`

```js
export const Config = z.object({
  drawer: z.boolean().default(true).description('输入框旁边的箭头抽屉').volatile(),
  sidebar: z.boolean().default(true).description('右侧栏的「任务」标签页').volatile(),
});
```

**每个要在设置页出现的字段都必须 `.volatile()`。**

源码（`dsh-settings`）：

```js
function volatileForm(schema) {
  if (schema.meta.volatile) return plainSchema(schema);
  if (schema.type === 'object') {
    const dict = Object.fromEntries(Object.entries(schema.dict ?? {}).flatMap(([key, child]) => {
      const field = volatileForm(child);
      return field === undefined ? [] : [[key, field]];
    }));
    return Object.keys(dict).length === 0 ? undefined : z.object(dict);
  }
}
```

没有 volatile 的字段**被整个丢掉**；全都不是 volatile 就返回 `undefined`，
于是这个 namespace 不进 `configurations`，`formFor(id)` 返回 undefined，
客户端拿到 `props.form === undefined`，页面空白。

**「volatile」的含义**：改完立刻生效，**不需要重新挂载插件**。

副作用：`apply` 不会再被调用。所以「在 apply 里按 config 决定注册不注册」
这件事，从机制上就不可能跟着开关走。要在组件渲染时判断（返回 null）。

## 三、配置界面：三个 slot

DSH 给插件挂配置界面用的 slot：

| slot | key | 出现在哪 | 适合 |
|---|---|---|---|
| `plugins.item` | 自己的 id | 官方插件区 | **官方包专用，别动** |
| **`plugins.bundle.config`** | **bundle 包名** | bundle 页，描述和行列表之间 | 整个 bundle 一份配置 |
| `plugins.row.config` | `<bundle包名>#<rowId>` | 某一行的配置按钮 | 每行一份配置 |

`plugins.item` 的 catalog 原文：

> OCCUPIED by the official settings pages, one companion package per
> host-plane namespace; **a bundle's configuration belongs in
> `plugins.bundle.config` or `plugins.row.config` instead.**

### 正确的注册写法（照抄官方 cot-translation）

```js
ctx.slots.inject('plugins.bundle.config', () => ctx.slots.register({
  name: 'plugins.bundle.config',
  key: '@local/taskboard',        // ← bundle 包名
  locale: NS,                      // 可选
}, Component));
```

官方原文（`@deepseek-ai/dsh-experimental-client-ui-cot-translation/lib/client.js`）：

```js
ctx.slots.inject("plugins.bundle.config", () => ctx.slots.register({
  name: "plugins.bundle.config",
  key: "@deepseek-ai/dsh-experimental-cot-translation-bundle",
  locale: NS,
  inject: () => {
    const face = form.inject();
    return { ...face, hooks: { ...face.hooks, availableProviders } };
  }
}, TranslationSettings));
```

## 四、踩过的四个坑

### ① key 是 bundle 名，不是 row 自己的包名

任务板的 bundle 是 `@local/taskboard`，UI 是 row `taskboard-ui`。

```js
key: '@local/taskboard'                                  // ✅ bundle.config
key: '@local/taskboard#taskboard-ui'                     // ✅ row.config
key: '@local/taskboard-ui#taskboard-ui'                  // ❌ bundle 名写错了
key: '@local/taskboard#taskboard'                        // ❌ 拆包前的旧结构
```

源码（`dsh-client-ui-plugin-manager`）：

```js
function rowConfigKey(bundle, rowId) { return `${bundle}#${rowId}`; }
const configured = ledger.bundles.has(openPkg.name);   // ← bundle.config 的判定
```

`pkg.name` 是**正在被打开的 bundle 的名字**。

### ② `props.form` 不会自动给

`plugins.bundle.config` 的组件拿不到 `props.form`。官方是自己 `ctx.configForms.get(ns)`。

我的做法：apply 时把两个 `ConfigFormController` 记进 module 级 Map，
卡片里 `props.form ?? settingForm(ns)` 取。

登记时机（apply 里）：

```js
rememberSettingForm('taskboard-ui', ctx.configForms.get('taskboard-ui'));
rememberSettingForm('taskboard-templates', ctx.configForms.get('taskboard-templates'));
```

**namespace = patch 里的 `id`**（`taskboard-ui`），不是 `include:taskboard-ui`。

源码（`dsh-settings` 的 describe）：

```js
ns: entry.options.id
```

### ③ 字段路径跟着 schema 走

Config 从嵌套 `ui.drawer` 改成平铺 `drawer` 之后，
设置卡还在读 `document.ui.drawer`、写 `path: ['ui', key]` → 值永远是默认。

改完：

```js
const valueOf = (key) => (typeof document[key] === 'boolean' ? document[key] : true);
form.mutate([{ op: 'set', path: [key], value }], revision);
```

注意 ops 的字段名是 **`op`**（不是 kind），`path` 是数组。
`props.form` 的形状是 `{ state, mutate }`，**没有 subscribe/getSnapshot**。

### ④ `ctx.slots.inject` 的回调是延迟执行的

slot 声明之后才跑。所以：

```js
ctx.slots.inject('plugins.bundle.config', () => { ... });   // 这里什么都不发生
```

不代表失败。要验证是否真的注册，看这些：

- `cordis_inspect_query(Slots, listSubTree, { root: 'plugins.bundle.config' })`
  的 `keyDomain` 里有没有你的 key
- 页面上 `document.querySelectorAll('[data-plugin-config]').length`
- 页面文本里有没有你组件的文案

## 五、怎么把配置变成「二级菜单」

现在任务板用的是 `plugins.bundle.config`，配置**直接摊在卡片上**，没有折叠。

想要「点进去才是二级页面」，两个做法：

### A. 用 `plugins.row.config`

```js
ctx.slots.register({
  name: 'plugins.row.config',
  key: '@local/taskboard#taskboard-ui',
}, SettingsCard);
```

效果：**那一行右边出现配置按钮**，点进去是二级页。
但这是**每一行一份**配置页。

### B. 保持 `bundle.config`，卡片上一行摘要 + 自己渲染详情页

卡片只显示一句摘要（`view: 'summary'`），点击后切到自己的详情（内部 state）。

`view` 的语义（slot ownerProps 原文）：

```ts
export interface PluginConfigViewProps {
  /** `summary` renders the one-liner alone, as text or inline nodes;
   *  `page` renders the form with its save control. */
  readonly view: 'summary' | 'page'
  readonly form?: ConfigPageForm | undefined
}
```

**B 更贴「一个任务库」的诉求**（整个 bundle 一份配置），
A 则是每行分开。目前实现选了 bundle 级。

## 六、怎么验（这次用的方法）

### 无头/隔离 profile

已有的现成环境（见 `无头配置.md`）：

```
C:\Users\16229\.dsh\profiles\<name>\         ← 独立 profile
X:\temp\dsh\探针\asar\out\...\bin.js         ← 从 app.asar 解出的宿主
```

起一个只属于测试的 web UI，**完全不碰 desktop**：

```
node X:\temp\dsh\探针\asar\out\dsh\node_modules\@deepseek-ai\dsh\lib\bin.js ^
  --profile tbtest --port 52019 --no-open
```

它会打印 `http://127.0.0.1:52019/?token=...`。

### 用 CDP 驱动浏览器验证

```
msedge.exe --remote-debugging-port=9333 --user-data-dir=X:\temp\dsh\探针\edge-profile ^
  --new-window "http://127.0.0.1:52019/?token=..."
```

然后从 `http://127.0.0.1:9333/json/list` 找页面的 `webSocketDebuggerUrl`，
用 WebSocket 发 `Runtime.evaluate` / `Page.captureScreenshot` /
`Input.dispatchMouseEvent`。

**关键：React 的合成事件不认 DOM 的 `.click()`**，必须用
`Input.dispatchMouseEvent`（`mousePressed` + `mouseReleased`）。

```js
await send('Input.dispatchMouseEvent', { type: 'mousePressed', x, y, button: 'left', clickCount: 1 });
await send('Input.dispatchMouseEvent', { type: 'mouseReleased', x, y, button: 'left', clickCount: 1 });
```

### 一条命令验配置有没有挂上

```
node .../bin.js --profile <name> --dump-config
```

输出里能看到每行最终的 `config`，比翻文件快。

## 九、一句话总结

**配置 = 宿主 schema + patch；界面 = 浏览器 slot 注册。
中间没有任何自动化。想让配置显示出来，必须两边都写。**

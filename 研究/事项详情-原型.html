创建（模板 GU · 用户任务）
  1. 状态操作全收进 ⋯ 菜单。菜单里还标了「可重开 / 不可逆」，下手前能看清后果。
  2. 父任务独立一行放在正文上面，因为它决定这条单挂在哪；下一行才是「展开关系」，子任务和依赖收在那里。
  3. 父任务行不占满，右边留给「派生子任务」——从这条直接建子任务，父任务自动填好。
  4. 交互区是引擎分析正文得出的，不是模板预先写好的能力清单；模板最多覆盖或删掉其中某一块。
  5. 备注固定在底部，不跟着内容滚。

为什么父任务和关系要分开

  • 父任务是唯一的一个，关系是任意多个。混在一起时看不出一条单挂在哪棵树上。
  • 父任务放正文上面，是因为它决定"这条单在整体里的位置"，比正文更靠前。
  • 关系默认收起：多数时候你只关心这条本身，需要时才展开看牵连。
  • 点父任务那一块直接跳过去，不用在树里找。

union 槽位：三层叠加，按 key 整份替换

交互区是一个 union，每个槽位有名字（derive、 choose、rank…）。 引擎分析正文得出默认，模板和工具再逐层按 key 覆盖。

叠加顺序

① 引擎默认（分析正文得出）
↓ 按 key 替补
② 模板 YAML 里声明的
↓ 按 key 替补
③ 调用工具时传的参数

怎么覆盖

  • 写哪个 key，就用你那一份整个替换那个 key 的内容——不做深合并。
  • 所以改一项时，要把这个 key 里的其他字段一起照抄，否则会丢。
  • 没写的 key 保留上一层的。

例：默认给「调研 / 设计 / 实现」三项。模板只想改「实现」的授权档， 就得把这个 key 完整写一遍（含它的模板代码、标题、授权档）， 其他两项自动保留。

要删掉某一项，是调用工具时传 null，不是写在模板里。

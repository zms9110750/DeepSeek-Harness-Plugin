# T-025 研究：自定义日志事件对会话加载的影响

- **问题**：能不能往会话日志里写自定义消息？写了之后，**停用 mod** 还能不能加载？
- **答**：能。但必须满足一个条件：`ignorable: true`。
- **证据**：宿主源码 + 本机真实日志。

---

## 一、宿主怎么判

`@deepseek-ai/dsh-session`（`lib/index.js`，94,940 字节）里有两个关键点：

```js
// 第 79 行：62 个已知事件类型
const KNOWN_SESSION_EVENT_TYPES = new Set([...]);

// 第 301 行：准入判定
if (!KNOWN_SESSION_EVENT_TYPES.has(event.type) && event.ignorable === true) return;
```

**这一行就是全部答案**：不认识的类型，只有 `ignorable === true` 才会被**安全跳过**。
否则继续往下走类型校验，最终**拒绝解释整份日志**。

还有第 1254 / 1267 / 1308 行，关于 `plugin:` 命名空间的约束：

```js
function isPluginRecordType(type) { return PLUGIN_RECORD_TYPE.test(type); }
// 第 1267 行
if (!isPluginRecordType(type)) throw new Error(`plugin record type "${type}" must be "plugin:" followed by lowercase slash-separated segments`);
```

即正式写法是 `plugin:<小写>/<小写>`。

源码注释里也把设计意图写得很清楚：

> Unknown ignorable records retain opaque metadata and never change the surface.

翻译：不认识的 `ignorable` 记录**保留原始数据，但不影响还原出来的会话**。

## 二、本机真实证据

我解了一份真实会话日志
（`C:\Users\16229\.dsh\sessions\--X-temp-dsh--\session-0e669cba-...\session.v4.jsonl.zstd`，
17.2 MB，10,144 个 zstd 帧，19,091 条事件）。

里面已经有**自定义插件事件**在跑：

```

"plugin:plan-tree/node": 62
```

这 63 条自定义事件，**没有影响加载**——整份日志能完整解析出 19,091 条事件。

它们长这样：

```json
{"type":"plugin:plan-tree/node","seq":5482,"time":1792416060633,
 "data":{"op":"file","id":"n4",...},"ignorable":true}
```

注意末尾的 `"ignorable":true`。

## 三、各种写法的判定结果

| 写法 | 结果 | 原因 |
| --- | --- | --- |
| `plugin:foo/bar` + `ignorable:true` | ✅ 安全 | 未知类型 + ignorable → 跳过（301 行） |
| `plugin:foo/bar` **不带** `ignorable` | ❌ **整份日志被拒** | 未知且不可忽略 |
| `plugin:foo/bar` + `ignorable:false` | ❌ **整份日志被拒** | 同上（false 不等于 true） |
| 任意名 `t025-probe` + `ignorable:true` | ✅ 安全 | 只要不在已知集合里 + ignorable 就行 |
| 任意名 `t025-probe` 不带 `ignorable` | ❌ **整份日志被拒** | 同上 |
| 覆盖已知类型 `user/message` + `ignorable:true` | ⚠️ 走正常校验 | 已知类型不会被跳过，ignorable 无效，还缺必填字段 |

## 四、回答你的两个问题

### 1. 能不能加自定义消息？

**能。** 两个条件：

- `type` 用 `plugin:<小写>/<小写>` 命名（正式写法，会被 `appendPluginRecord` 强制）
- **必须** `ignorable: true`

### 2. 日志存在，但停用 mod 之后还能不能加载？

**能。** 这正是 `ignorable: true` 的全部意义：

- 有它 → 加载器遇到不认识的类型，**保留记录但跳过**，会话照常还原
- 没它 → 加载器认为这是一份"看不懂的日志"，**拒绝解释整份**

所以「停用 mod 后日志打不开」这个风险，**完全取决于有没有写 `ignorable: true`**。

## 五、真实失败模式

`计划\15-计划即提案\README.md` 里记的那次事故，就是这个：

> **不要用 `session.append` 写自定义类型**：写出的是"未知且不可忽略"，
> 加载器会**拒绝解释整份日志**。

对应本研究的结论：用 `session.append` 而不是 `appendPluginRecord`，
就不会带上 `ignorable: true`，于是踩坑。

正确的 API 是 `appendPluginRecord`——它强制 `plugin:` 命名空间并标 `ignorable:true`。

---

## 六、对 taskboard 的意义

taskboard 现在**不写会话日志**，只写自己的 `plans.jsonl`，所以暂时不受这套规则约束。

但如果以后要让计划事件进会话日志（例如「面板里看到的状态变化也出现在对话流里」），
就必须：

1. 走 `appendPluginRecord`
2. type 用 `plugin:taskboard/<动作>`
3. 确保 `ignorable: true`

否则一旦停用 taskboard，那份会话可能就打不开了。

**这也是为什么 T-019 选择把事件写进自己的 JSONL，而不是会话日志**——
独立存储不会牵动会话加载。这个决定在这次研究之后看是对的。

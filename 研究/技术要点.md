# 技术要点：这台机器上的 DSH 是怎么组成的

都是这一轮**亲手验证过**的，不是文档抄的。

---

## 一、进程结构（决定了能力边界）

```
16920  DeepSeek Harness.exe                    主进程，窗口在这里
 ├ 17344  --type=renderer                      页面（Web UI）
 ├ 24328  --type=utility --utility-sub-type=network.service
 └ 18980  --expose-internals dsh-desktop-host\lib\index.js   ← Host 在这里
     └ 17732  dsh-subprocess-local\runner.js
```

**结论：Host 跑在 Electron 的 utility 进程里。**

后果：

- `webContents` / `BrowserWindow` 对插件**不可见** —— 想从 Host 截屏，此路不通；
- `require('electron')` 能成功返回，但里面没有 `BrowserWindow`（会拿到 npm 那个 stub）；
- 所以「对窗口截图」只能走操作系统层：`user32!PrintWindow` + `PW_RENDERFULLCONTENT`（已实测成功，1936×1056）。

## 二、插件是什么

一个普通 ESM 模块，导出四样：

```js
export const name = 'my-plugin'
export const inject = ['tools']          // 需要的服务
export const Config = z.object({ ... })  // 可选，配置 schema
export function apply(ctx, config) { ... }
```

要成为可安装的 **bundle**，`package.json` 里加：

```json
"dsh": { "bundle": { "patch": "./cordis.patch.yml" } }
```

patch 里就是一行 `- insert:` 指向包名。

## 二点五、工具卡片是谁画的

`defineTool` 里可以写 `presentCall()` / `presentResult()`，但**Web 客户端不消费它们**
（`dsh-tools` 的 README 原话：*"The built-in Web Client does not consume those values."*）。

真正的渲染走客户端插槽 `tool.call.toolview`，按工具名 keyed，props 来自
**原始参数、结果内容、失败状态、持久化元数据**。

含义：

- 想在卡片上显示"这次调用在干什么"，要么把注释作为**真实参数**写进 schema，
  要么自己注册一个 `tool.call.toolview` 渲染器；
- `presentCall` 只能给 Host 本地的消费者用，对界面无效 —— 别照它设计。


## 三、三个已经踩过的坑

### ① 插件目录必须有它自己的 `node_modules`

Node 解析依赖用的是**真实路径**，不是链接路径。插件放在 `X:\...\plugins\a\` 时，`import '@deepseek-ai/dsh-tools'` 会从 `X:\...` 往上找，找不到就 `ERR_MODULE_NOT_FOUND`，插件**装上了但永远 inactive**。

解法：在插件目录里放一个 `package.json` 声明依赖，然后 `pnpm install`。只装真正 import 的那几个包。

### ② Host 侧的 JS 改了不会热更

改 `index.js` 之后立刻调用，**行为不变** —— 模块被缓存了。`dsh-hmr` 只对已加载的文件变化生效，新代码要等重启。

绕过办法（不用重启）：**换一个目录或包名重新 `install_bundle`**，新的真实路径 = 新的模块 URL = 重新加载。我这次就是靠 `screenshot-plugin` → `ui-capture` 换名才验到修正版。

### ③ 移动插件目录会让 junction 失效

`install_bundle` 建的是指向目录的链接。目录一挪，链接就断，profile 里那条 `+ pkg <- 旧路径` 会报错。移动后必须 `remove_bundle` + 按新路径 `install_bundle`。

## 四、界面插件

`package.json`：

```json
"dsh": {
  "bundle": { "patch": "./cordis.patch.yml" },
  "client": { "platform": "web", "immediately": true, "inject": ["@deepseek-ai/dsh-client-ui-renderer"] }
}
```

`client.js`：

```js
window.__ModuleLoader__.load({
  id: '@local/my-thing',
  factory(require) {
    const React = require('react')
    return {
      inject: ['slots'],
      apply(ctx) {
        ctx.slots.inject('shell.overlay', () => ctx.slots.register(
          { name: 'shell.overlay', id: 'my-thing', order: 5 }, MyComponent))
      },
    }
  },
})
```

**客户端插件是即时生效的**（注册进插槽树后 `active: true`，不需要重启），和宿主侧相反。

常用插槽：

| 插槽 | 位置 | 性质 |
|---|---|---|
| `shell.overlay` | 全窗口浮层，在所有列之上 | 可点穿，加东西不替换 |
| `conversation.composer.dock` | 输入框下方 | 有分配空间 |
| `settings.section` | 设置页一页一个 | 加整页 |
| `settings.general.item` | General 里一行 | 加一个开关 |

## 五、沙箱现状

**confined 模式下所有 shell 命令直接失败**：

```
sandbox-local windows-acl temp grant materialization failed and its cleanup also failed
```

不是权限不足，是沙箱自己建立临时授权失败。所以本轮每次 `git` / `pnpm` / `pwsh` 都用了完全权限。

影响：任何「需要跑命令」的计划，都要么先修沙箱，要么全程提权。

## 六、现有产物

`发布/ui-capture/` —— 截图工具，可用。实现要点：

1. Host 侧 `spawn` 一个 `powershell.exe` 跑 `capture.ps1`；
2. 脚本按进程名找有 `MainWindowHandle` 的窗口，`PrintWindow` 抓表面；
3. 存 PNG，工具读 PNG 头（偏移 16/20）拿宽高，`stat` 拿字节数；
4. 找不到窗口就报 `no visible Harness window` —— 这就是「仅在有 UI 渲染时可用」的落点。

局限：抓整窗（含标题栏）；窗口最小化时可能失败或全黑。

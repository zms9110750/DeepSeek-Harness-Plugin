# 引用式分叉存储：内置 sqlite、fork 溯源、以及怎么真的按引用存

调查对象：`dsh 0.2.1-rc.2`（活体 + 解包副本 `探针\asar\out\dsh\`）。只读，`pwsh` 仍不可用。

---

## 1. 内置 sqlite（`dsh-session-query-sqlite`）是怎么做的

**它是"派生、可丢弃"的全文检索读模型，不是权威存储。**（`README.md:12,87`）

**文件与保护**
- `Config.path` 必填、无默认，可 `:memory:`；缺文件按 0600/0700 创建（`lib/index.js:41-49`）。
- `PRAGMA application_id = 1146308689`、`user_version = 8`（`:83,117`）。不是本应用的库、
  或表名不认识 → 直接拒（`:56-57,74-77`）；版本不符 → 就地 drop 重建（`:60,78-81`）。

**三张表**（`:82-146`）
```sql
search_state(singleton, global_generation)                    -- 全局代号
persisted_sessions(id PK, version, created_at, cwd, parent_session, seed_length,
                   delegation_depth, agent_preset, revision, generation)   -- STRICT
persisted_docs USING fts5(text, session_id UNINDEXED, seq UNINDEXED, type UNINDEXED,
                          time UNINDEXED, surface UNINDEXED, codepoint_length UNINDEXED,
                          tokenize='unicode61')               -- 一行 = 一条语义事件的文本
-- 连接内再有两张 TEMP 孪生：live_sessions / live_docs（尚未落盘的活跃会话）
```

**同步：不是监听事件，而是"每次查询前对账"**（`:646-756`）
1. 取 `persistence.list()` 快照；
2. 与 `persisted_sessions.revision` 比：相等 → 跳过（`:721`）；
3. 不等 → `persistence.open(id,'read')` + `handle.read(0)` **整份读**（`:724`），
   然后**删掉该会话所有文档行、整份重插**（`_replacePersistedSession` `:770-786`）——
   会话内不是增量；
4. 前后各取一次 `list()` 快照，不一致就重试（`:730-733`），防读到写了一半的语料；
5. 活跃会话走内存：对 `{header, inheritedEventCount, events}` 算 SHA-256 指纹，
   与 TEMP 表比（`:997-1010`）；
6. 所有写在一个 `BEGIN IMMEDIATE … COMMIT` 里（`:679-690`）。
- `persistence` 服务实例换了 → epoch++，全量重读（`:663,701-702`）。
- 游标里带 `generation`，过期报 `SESSION_QUERY_STALE_CURSOR`。
- 公开 API 只给 `searchSessions / searchEvents / filterSessions / traceSession / readSession…`；
  `seed_length` 只投影、不外露（`rowHeader` 只回 `isSeeded: row.seed_length !== null`）。

**对你的意义**：它每次 revision 变化就整会话重读重插，所以"大量 fork"会让它写入放大；
而且 FTS 里每个 fork 都有一份前缀文本 → 索引体积 O(分叉数 × 前缀)。

## 2. fork 的"来源 + 行"已经记了三次

| 载体 | 内容 | 证据 |
|---|---|---|
| 物理 header 首行 | `parentSession`、`isSeeded` | v2 编码器 `format-v1-to-v2/lib/index.js:279-295`（`parentSession` 在 `:289`）；读回 `jsonl/lib/index.js:827-842` |
| 日志内 | `session/end-seed { inherited: true }`，**它的 seq 就是切点** | `dsh-session/lib/types/fork.js:18-27`：marker 放在 `boundary+1`；`inheritedEventCount = boundary+1` |
| 检索库 | `persisted_sessions.parent_session`、`seed_length = inheritedEventCount` | `session-query-sqlite/lib/index.js:919`（`header.isSeeded ? inheritedEventCount : null`） |

读法：
- 血缘：`ctx.sessionQuery.traceSession(id)` → `{ancestors, descendants, root, complete}`（只给会话，不给 seq）。
- 按父过滤：`filterSessions([{kind:'parent', values:[...]}])`。
- 行：`readSession(id)` / `observeSession(id)` 返回 `inheritedEventCount`；或直接 SQL 查索引库。

**结论：不需要新建"来源表"；缺的是让存储真的按引用走。**

## 3. 引用式存储必须伪造/满足什么（硬约束）

来自 `dsh-session` 与各消费者，逐条都能把设计打死：

1. **事件数组必须 0..n-1 稠密、`index === seq`**：`deriveMessages()` 用 `this.log[seq]`；
   `SurfaceManager` 以 `baseSeq=0` 折叠；`assertDeveloperHeader` 用 `events[headerSeq-baseSeq]`。
   → `handle.read(0)` 必须返回**完整逻辑日志**，不能"只给后缀"。
2. **tagged marker 必须在 cut 处，且是最后一个 tagged marker**（构造器与格式检验都断言）。
3. **`inheritedEventCount` 必须由 provider 回传**，不许从 `firstLiveSeq`/标记反推。
4. **`isOwnSeq(seq) = seq >= cut`** 的语义不能变：subagent descriptor/catalog/delivery、
   history 的 descriptor 寻址、schedule 的 fold 都靠它区分"自己的后缀"与"继承来的前缀"。
5. **`surfaceOp: replace` 与 `sourceEventSeqs` 可以跨 cut 引用** → 前缀节点必须真实存在于折叠里。
6. **`time` 原样**（`buildForkSeed` 取 `events[boundary].time`）。
7. resume 读全文（`agent-loop:1989` → `handle.read(0)`），`SessionStore.fork` 要求源会话**是活的**
   （`SESSION_NOT_LIVE`）；UI 的 fork 走 `api-session-controller`，可以冷读源。
8. 打开即校验全量：`open()` 会整份读 + `validateStoredEvents`；`stat`/`list` 只读 header。

## 4. 设计：一树一库，只存后缀 + 指针

```sql
-- 会话目录（可复用 18/C-01-01 的 sessions 表，补两列）
CREATE TABLE sessions(
  id         TEXT PRIMARY KEY,
  parent     TEXT NOT NULL,
  cut        INTEGER NOT NULL,   -- = inheritedEventCount = marker 的 seq = 父的 boundary+1
  header     TEXT NOT NULL,      -- 完整 SessionHeader JSON
  prefix_sha TEXT,               -- 父 [0,cut) 的 sha256，首次合成时写；用于 fail-closed 校验
  own_events INTEGER NOT NULL,
  own_bytes  INTEGER NOT NULL,
  rev        INTEGER NOT NULL    -- 每次写 +1
) STRICT;

-- 只存自己的事件（marker 在 seq == cut，属于自己这侧；[0,cut) 不存）
CREATE TABLE events(
  sid  TEXT NOT NULL,
  seq  INTEGER NOT NULL,
  type TEXT NOT NULL,
  json TEXT NOT NULL,
  PRIMARY KEY(sid, seq)
) WITHOUT ROWID;
```

**写**
- `create(header,{inheritedEventCount})`：只登记行（parent=header.parentSession, cut, header），不落前缀。
- `append(events)`：断言首 seq == 下一个逻辑 seq；**丢弃 `seq < cut` 的（就是那段前缀）**，
  其余一个事务写入并 `rev++`。注意 marker（`seq == cut`）要留下——它是切点的唯一凭证。
- 语义等价：`create` + 首次 `append`（agent-loop 的 `appendUnstoredSuffix` 会把**整段 seed**
  通过 handle.append 交给你）→ 你有机会校验前缀、算出 `prefix_sha`，然后只写后缀。

**读（合成）**
```
read(offset, length):
  end = offset + length
  if offset >= cut: 直接本表
  else: 前缀 = chain(parent, offset, min(end, cut)) ；再接本表 [cut, end)
chain(id, from, to):
  row = sessions[id]
  if from >= row.cut: 本表 [from,to)
  else: chain(row.parent, from, min(to,row.cut)) + 本表 [row.cut, to)
```
- 父可能是根会话（原版 JSONL 里）或另一个引用子会话。
- 前缀**不可变**（seam 保证已提交事件永不改写）→ 可以进程内 LRU 缓存合成结果，
  并把它深冻结后以 `shared-frozen` 返回。
- `prefix_sha` 首次合成时校验；不符 → fail-closed（当作损坏，别猜）。

**stat / list / revision**
- `revision`：必须是字符串，且"相等 = 未变"。用 `ref:{rev}:{cut}:{parent-handle}` 即可，
  因为父的 `[0,cut)` 永不变化。
- `eventCount = cut + own_events`；`sizeBytes` 只报自己那份（可选字段，语义自定）。
- `formatStatus` 可省。

**失败模式（都写清楚，别默默兜底）**
- 父缺失/损坏 → 子会话打不开（`18/A-问题.md` 第 4 条已接受）。
- 卸载 mod → 子会话全部打不开，根不受影响。
- 跨进程单写：seam 只保证进程内；sqlite 需要自己的租约或明确"单进程"。
- `open('write')` 的整份读：合成本质上要读全链 → 冷读成本 O(链上事件总数)。

## 5. 接法：门面 provider（不换服务名）

`session-fork-bridge2` 已验证"包活实例 + `ctx.effect` 恢复"可行；持久化这里同样用门面，
但范围只限**你自己登记的引用子会话**：

| 方法 | 行为 |
|---|---|
| `create(header, {inheritedEventCount})` | `header.isSeeded && header.parentSession` 命中你的策略 → 返回**你自己的 handle**，不调原版；否则 delegate |
| `open(id,'read'\|'write')` | 你的库里有 → 自己的 handle；否则 delegate |
| `stat` / `list` | 合并（原版快照 + 你的行；`revision` 用你的字符串） |
| `flush()` | `原版.flush()` + 排空你的写队列 |
| 事件路由 | **自己** `ctx.on('session/event' / 'session/flush' / 'session/disposed')`。原版的监听器只查它自己的 `writers` 表，你的会话不在里面 → 原版静默不写（正合需要，`jsonl/lib/index.js:421-424` + `README.md:57`） |

关键好处：**不用动 fork 代码**。子会话的 seed 本来就会经 `appendUnstoredSuffix`
（`agent-loop:1881-1886`）以一次 `handle.append` 交到 provider 手里，你在 receive 侧丢掉前缀即可。
B-02 设想的"建会话时拦 create"其实不必——`create` 只给 header，真正的前缀在 `append` 里。

## 6. 大量 fork 的成本模型

| 环节 | 现在 | 引用式之后 |
|---|---|---|
| 磁盘 | 每个 fork 一份前缀（实测 5.1 MB/次） | 只有自己的后缀 ✔ |
| 创建 | 前缀深拷贝（`snapshotJsonValue`+`deepFreeze`）+ zstd 压缩 + fsync 前缀 | 仍要深拷贝与 append 一遍；省掉压缩与 fsync 的大部分（这才是 fork 卡顿的来源） |
| 冷读/resume | 读自己那份 = 全量 | 读链：O(链深) 次查询 + 全量事件；**不比现在便宜** |
| 检索索引 | 每会话全文入 FTS | **仍然每会话全文入 FTS**（索引读的是逻辑事件）→ N 个 fork = N×前缀文本，且每次 revision 变化整会话重插 |
| 内存 | 每个活着的 fork 持全量前缀 | 一样 |

**索引是最大的隐藏成本**。两条出路：
1. 树内子会话不进内置索引（`list()` 里不暴露，或另配一个不接 `sessionQuery` 的 provider 实例）——
   代价是全局搜索/侧边栏看不到它们，只能走你自己的树 UI；
2. 自建引用感知索引：`texts(hash TEXT PRIMARY KEY, text)` + `docs(hash, sid, seq)`，
   fork 时只插 `(hash, newSid, seq)` 映射，不重复存正文。

链深：`fork(fork(...))` 会把链拉长；冷读 O(深度)。加阈值 K（如 8）：超过就把前缀物化进自己这层
（一次复制，摊到后续读），类似 log-structured 的 checkpoint。

## 7. 落地顺序（建议）

1. **先用现成的**：`parentSession` / `seed_length` / `traceSession` / `filterSessions(parent)`，
   零代码就有"来源 + 行"；先量一量 100 次 fork 的真实磁盘与耗时。
2. **门面 MVP**：只接管"树内子会话"，**先只支持一层**（parent 必须是根）；
   根照旧原版写。跑通 create/append/read/list/stat/flush。
3. **加链与校验**：prefix_sha、LRU、深度阈值 checkpoint。
4. **再决定索引**：排除子会话，或自建去重索引。

## 8. 风险清单

- provider 一坏，**所有被接管的子会话全丢**；根不受影响（隔离设计是优点，但恢复面只有 `/tree-expand`）。
- 版本：0.2.1-rc.2 的构造器/格式断言很密；`dsh-session` 升级时这些断言就是你的回归测试点。
- 契约测试套件（`runPersistenceContract` / `runLiveWritePathContract`）不随包发布，只能自测。
- 与 Claude Code mods 无关：那条桥不碰日志（`$.session.append` 无实现）。

# 待查清单

按"查到就能推进"排序。每条都写清楚**查什么、为什么要查、查到之后能做什么**。

---

## 高优先（卡住整条线）

### 1. dsh 到底有没有 MCP 客户端插件

- 查：npm 搜 `dsh mcp`、GitHub 搜 `dsh mcp client`、以及 `@deepseek-ai` 组织下的包列表
- 为什么：决定需求 2.1 是"装一个"还是"写一个"
- 查到后：能装就省一周

### 2. MCP 四个注解的官方语义

- 查：`modelcontextprotocol.io` 的 Tool annotations 一节
- 要确认：`readOnlyHint` / `destructiveHint` / `idempotentHint` / `openWorldHint` 的**默认值**和**谁有权设置**
- 为什么：需求 2.2 的四个开关直接照它实现；默认值猜错就会误拦或漏拦
- 查到后：能直接定 UI 语义

### 3. 沙箱为什么坏

- 现象：`sandbox-local windows-acl temp grant materialization failed and its cleanup also failed`
- 已知：我修好了工作区的 WRITE_OWNER，但临时授权那一步仍然失败
- 为什么：MCP 的 stdio transport、git、pnpm 全都要起子进程；沙箱坏着，这一整条线都得靠提权
- 查到后：所有计划都能在正常权限下跑

---

## 中优先（影响实现选型）

### 4. mihomo 能不能按连接分流

- 查：`PUT /proxies/{name}/select`、`GET /rules`、`/connections` 的能力
- 要确认：能不能"只让某一条连接走某组"，而不是切全局模式
- 为什么：需求 2.3 的核心约束是"不得开全局"
- 查到后：能决定是"进程级 env 注入"还是"请求级 dispatcher"

### 5. DSH 的内嵌浏览器面板是 webview 还是 iframe

- 查：`@deepseek-ai/dsh-client-ui-sidebar-browser` 的实现
- 为什么：决定 4.1 侧边栏能不能直接嵌 chat.deepseek.com（X-Frame-Options 会挡 iframe）
- 查到后：能确定侧边栏是"加个书签"还是"要自己写容器"

### 6. 同名工具能否覆盖

- 查：`ctx.tools.register` 同名时的行为
- 为什么：需求 3.1（并发节流）最干净的实现是"同名覆盖原 subagent"
- 查到后：能少写一个新工具名

---

## 低优先（可以先做再查）

### 7. 会话 fork 的真实语义

- 查：fork 出来的会话是否共享工作区、是否共享缓存前缀
- 为什么：需求 3.4 的"分支"打算用 fork 拼，得知道它到底复制了什么

### 8. DSH 的 projection 能不能被 UI 直接读

- 查：`wire.viewSchema/view` 之后，客户端怎么订阅
- 为什么：树视图（4.2）要靠它

### 9. 快照存哪

- 这其实是**要和你商量**的，不是查出来的：工作区内 `.dsh/snapshots`、还是 DSH_HOME、还是 sqlite
- 三个方案各有代价，见 `计划/01-工作区与治理.md` 1.3

# 沙盘

两个**完全隔离**的部分。各自的目录、进程、端口、数据。

| | 收件箱 | 工作区 |
| --- | --- | --- |
| 目录 | `inbox/` | `work/` |
| 进程 | 一个 node | 另一个 node |
| 端口 | **52311** | **52312** |
| 源码 | `inbox/_src/`（冻结） | `work/_src/`（跟着改） |
| 构建 | `inbox/build.mjs` | `work/build.mjs` |
| 产物 | `收件箱.html` | `工作区.html` |
| 数据 | `收件箱.json` / `收件箱-草稿.md` / `收件箱-提交记录.jsonl` | `工作区.json` / `工作区-笔记.md` |
| API | `/api/inbox` | `/api/work` |

## 启动

```
node start.mjs
```

或者分开起：

```
cd inbox && node server.mjs 52311
cd work  && node server.mjs 52312
```

- 收件箱 → http://127.0.0.1:52311/
- 工作区 → http://127.0.0.1:52312/

## 为什么连端口也要分

用户原话：

> 既然分区了那为什么还是同一个端口

一个端口 = 一个进程。目录分开但服务共用，等于改坏一处两边都起不来。
所以三个维度都分开：

```
目录   inbox/        work/
进程   两个 node     两个 node
端口   52311         52312
```

我改 `work/server.mjs`，收件箱的服务照常跑；收件箱服务挂了，工作区不受影响。

## 收件箱：用户用

**冻结在 2026-10-27 21:53 那一版**——用户派 GU-03 / GU-04 时的样子。

能做的事：

- 派一条（标题 / 模板 / 父任务 / 关系 / 高级设置）
- 看科技树 / 列表
- 改状态、编辑正文
- 底部写自由文本

AI 读三个文件就能拿到指令：`收件箱.json`、`收件箱-草稿.md`、`收件箱-提交记录.jsonl`。

## 工作区：AI 用

**改版试验场。** 格式随时会变。

比收件箱多出来的：

- 过滤二级菜单（状态 / 类别 / 领域，三级占文档流）
- 七种关系图例（父子 / 依赖 / 派生 / 来源 / 相关 / 约束 / 参考）
- 详情页头部重排（编号在左半行 + 类别领域两个标签，标题 19px）
- 新建时能看到「模板怎么选行动」（章节 → 行动的预览）
- 五个行动全部接入（text / markdown / ask / rank / derive）

## 构建

```
cd inbox && node build.mjs
cd work  && node build.mjs
```

每个 `build.mjs` 自检三件事，不合格直接抛错：

1. 标签平衡（script / html 各一个）
2. 函数不重复
3. 脚本能通过 `new Function` 解析

## 技术备注

- 服务只绑 `127.0.0.1`
- 页面保存有 600ms 防抖
- 服务没起时（直接双击 HTML）退回内置样本并提示「本地模式」
- 两边页面右上角互相有链接（绝对地址，跨端口）

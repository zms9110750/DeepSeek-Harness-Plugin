# 沙盘

两份 HTML，服务于两件不同的事。**数据完全隔离，不共用。**

```
启动：node server.mjs 52310
```

## 收件箱（`/`）—— 你派活给我

**这是你用的。** 你在里面写，内容落盘，我直接读文件。

| 落盘文件 | 内容 |
| --- | --- |
| `收件箱.json` | 列表里的条目（id / 标题 / 状态 / 正文 / 父任务） |
| `收件箱-草稿.md` | 底部自由文本（列表写不下的东西） |
| `收件箱-提交记录.jsonl` | 每次保存追加一条带时间戳的快照 |

我能拿到的：

- **哪条是新的** —— 对比 `收件箱-提交记录.jsonl` 的最后几条
- **你说了什么** —— `收件箱-草稿.md` 就是散文，我直接读
- **结构化的活** —— `收件箱.json` 里有 id、父任务、状态，我能按依赖排序

所以你可以：

- 在列表里一条条派（右边能填标题、状态、类别、模板、正文）
- 在底部写整段话（"这个版式我不满意，改成……"）
- 改数据格式也行 —— 我读不出来会问你，不会瞎猜

## 工作区（`/work`）—— 我改版用

**这是我的。** 数据也落盘（`工作区.json`），但和收件箱完全无关。

用途：试破坏性改版。版式、数据结构、渲染方式都能推翻重来。
如果我改坏了导致读不出来，刷新一下或者点「重置为样本」就行 —— 不影响你那边。

你现在是旁观者，看到的就是我改成什么样。

## 为什么分两份而不是一份

你原话：

> 这两个是隔离的。他们不共用数据。因为连数据格式都要在后者里面
> 进行决定。会有破坏性更新，等会可能读不出来。

一份数据两个用途会互相牵制：我改格式时，你刚派的任务可能就读不出来了。
分开之后，你那边的格式可以稳定，我这边随便折腾。

## 技术备注

- 服务只绑 `127.0.0.1`，不暴露到局域网
- 页面保存有 600ms 防抖，不会每敲一个字发一次请求
- 服务没起时（直接双击 HTML）会退回内置样本，并提示「本地模式」
- 两边都从这 9 条真实样本起步，之后各自演化

# D-实现-02

## 解析：标签扫描，不用 DOM

按出现顺序识别三种记号：`<DL>`（开层）、`</DL>`（闭层）、`<H3>`（文件夹）、`<A HREF>`（条目）。
行解析和 DOM 遍历都不稳：DOM 版在 linkedom 下 0 条，浏览器里又只对一半。

## 踩过的四个坑

1. **顺序**：把 item 和 child 分两个数组存，渲染时 items 全跑前面、文件夹全后置。
   改成单个 `entries` 数组按源顺序交错。
2. **重复 key**：文件里有 54 条重复 URL，用 URL 当 React key 会让同一行被重复挂载，
   反复开合"变多"。改用序号当 key。
3. **根节点被折叠**：根没有名字，折叠判断把整棵树当收起，页面空白。根强制展开。
4. **导入吞掉自建收藏**：导入是整体替换，所以「我的收藏」那三条会消失。
   改为加载时检查，缺了就补一组。

## 验证方式

`探针\parse-bookmarks-token.mjs` 用同一套逻辑在 Node 里跑，
输出 1866 条 / 1812 唯一 / 86 文件夹 / 顶层顺序 手机收藏→收藏栏。
界面结果必须与之逐项一致，不一致就是界面侧的问题。

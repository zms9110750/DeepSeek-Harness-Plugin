# 计划总览

一项需求一个目录；每项里 **A / B / C / D 各自成文件**。

## 为什么分开

一个 A（问题）可以对应多个 B（设计）：B-01 被否决、写 B-02 是常态，**被否决的保留**，因为它记录了"为什么不行"。
同理一个 B 可以对应多个 C（接口），一个 C 多个 D（实现）。

```
A-问题.md
   ├── B-设计-01.md ── C-接口-01.md ── D-实现-01.md
   ├── B-设计-02.md ── C-接口-02.md ── ...
   └── B-设计-03.md（否决，保留）
```

每个目录的 `README.md` 写状态：现在在做什么、研究到哪一步、什么还没开始。

## 贯穿所有项的约束

1. 不做烧 token 的真实验：狼人杀、长任务压测一律用最小样例。
2. 不用子 agent 做调研（用户明确要求），自己读。
3. 先把源码解出来再动手：`探针\asar\out\` 是 `app.asar` 的全量解包，可随时重新生成。
4. 客户端插件改代码要**换包名重装**才生效（同名的旧模块不刷新）；宿主侧换名或重启。

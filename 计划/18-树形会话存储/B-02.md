## B系列-设计（B-02）· 引用式分叉：各写各的文件

- 主要目标
  - **文件所有权分得干干净净**：
    ```
    <会话 GUID>/
        会话.jsonl.zst        ← 原版写，只有原版写，mod 一个字节都不碰
        树会话.jsonl.zst      ← 本 mod 写，只有本 mod 写
    ```
    根会话、普通会话：目录里只有 `会话.jsonl.zst`。树里的子会话：目录里只有 `树会话.jsonl.zst`。
  - 子会话的第一行是**指针**：`{"kind":"continuation","parent":"<父 GUID>","seq":4821}`，其后才是它自己的事件，一行一条、只追加。
  - 看「树-02-04-06」：读它的 `树会话.jsonl.zst` → 第一行指到 02-04 的第 4821 条 → 递归到根 → 拼成全文，给 UI 也发给模型。
- 次要目标
  - 磁盘上**不存在复制**：子会话那份 `树会话.jsonl.zst` 只含自己的事件 + 指针，父的前缀永远只在父自己那里。
  - 请求侧拿到的是拼好的全文（内存里持有完整事件），因此前缀字节与父完全一致，前缀缓存照旧命中。
  - 指针记 **seq**，不记行号：行号随压缩帧边界变，seq 稳定。
- 约束/许可/缺点
  - **约束**：树里的子会话**不能**让原版落盘，否则同一个 GUID 下会多出一份全量 `会话.jsonl.zst`，复制又回来了。分流点只在建会话那一刻：判断这个 id 是否属于某棵树，属于就不交给原版的 `create`。
  - **约束**：`树会话.jsonl.zst` 的改名不影响原版——原版只认 `会话.jsonl.zst`，看到别的文件名就当没有，所以两个文件可以并存于同一目录而不打架。
  - **缺点**：关掉 mod，这些子会话原版看不见（入口没了）；根会话不受影响。
  - **缺点**：树文件是自造格式，读它必须经本 mod；格式演进由本 mod 自己迁移。
  - **许可**：一个树节点的父既可能是另一个树节点（同格式，继续递归），也可能是根会话（换成读 `会话.jsonl.zst`，读到 seq 为止）。
- 被否决的替代
  1. **原版做法：子会话一个 `会话.jsonl.zst` 装全量**：整份复制父日志，实测 5 MB/次。
  2. **一棵树一个 tar 放在根目录里**：目录少，但要自造段格式与追加语义，第一版不值得。
  3. **结束后删原版那份**：动原版，且崩溃会丢数据。
  4. **只存后缀、读时按需拉取**：请求侧拿不到全量前缀，没有上下文也没有前缀缓存——与"一上来就吃 200k"的事实冲突。
- 工具
  - 写：建子会话时不走原版落盘；`treeSessions.register(guid, { parent, seq })` 写首行，之后事件逐条追加。
  - 读：`treeSessions.chain(guid)` 沿指针回溯到根，返回拼好的事件流（UI 与请求共用）。
  - 命令 `/tree`（列本树成员与指针）、`/tree-detach <guid>`（明说：只影响树文件，不碰任何 `会话.jsonl.zst`）。

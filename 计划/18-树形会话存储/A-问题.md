## A系列-问题

- 痛点/验收
  - **痛点**：分叉是"纯复制"。子会话目录里躺着父日志的整段前缀——这次实测每个子会话 5.1 MB，父 9.8 MB。一次会话里分叉十次就是五十兆。换来的只是 KV cache 命中，磁盘上却是一份份完全重复的字节。
  - 验收：
    1. **根会话永远是原版格式**，完整、自洽、不依赖任何 mod。它是最短的那条链，不该被别的机制碰。
    2. **一棵树的所有分叉存在一个文件里**（不是每个子会话一个目录）。树自己管这棵树有哪些会话、谁是谁的父、在第几条切开。
    3. **原始持久化服务照常运行**，树形存储**依赖它**：根会话仍由它写、由它读；树形存储只在"这个 id 属于某棵树"时接管。
    4. **mod 关掉后子会话打不开**——这是明确接受的。持久化文件留着，需要时另写 mod 去展开。本 mod 的成立前提就是它自己开着。
    5. **关掉 mod 不污染原版存储**：树形存储只写自己的文件，原版目录里不留半成品。
    6. 退化有保险：`/tree-expand <sessionId>` 把某个子会话的前缀写回成原版完整文件（或提供等价的导出），使它在 mod 关闭后仍可打开。
- 适用性
  - 只有"需要树形会话"的消费者在场时才启用（例如计划树派发子会话）。没有消费者，这个 mod 不该启动——它是给树用的，不是给普通对话用的。
  - 存储格式与 seq 语义：宿主的加载器要求 `inheritedEventCount` 不超过日志长度、偏移从 0 连续。所以子会话在树文件里存的是**自己的后缀**，读的时候由本 mod 沿父链把前缀拼回来再交给 `Session`；拼不回来（mod 关闭）就等于打不开。
- 先例
  - 原版持久化是一个**服务**（`sessionPersistence`，默认由 `dsh-session-persistence-jsonl` 提供），接口是 `create / append / list / load / remove`，按会话 id 寻址。服务名唯一，所以**不能再 `provide` 一个同名服务**——只能像 `session-fork-bridge2` 那样裹住活实例的方法，这也正好满足"依赖原版"。
  - `Session` 里已有 `inheritedEventCount` / `firstLiveSeq`：模型层本来就承认"我的日志开头有一段继承来的前缀"，前缀共享不需要改语义，只需要改存储。

## C系列-接口（C-01-01）· 树的库：表、写入、读取

- 功能
  - **一个文件**：`<根会话 GUID>/treeSession.db`（sqlite，一棵树一个）。原版的 `会话.jsonl.zst` 就躺在它旁边，两边互不认识。
  - **两张表**，各管一件事：
    ```
    sessions(id TEXT PRIMARY KEY, parent TEXT, at_seq INTEGER, plan_id TEXT, created_at INTEGER)
    events(session_id TEXT, seq INTEGER, line TEXT, PRIMARY KEY(session_id, seq))
    ```
  - `sessions` 一行 = 树上一个节点：它叫什么、从谁分出来、继承了多少条。`parent` 为空表示"接根会话"。
  - `events` 一行 = 一条事件，`line` 是**原始 JSONL 那一行**，不做任何拆字段。`seq` 从 0 连续。
  - **`at_seq` = 从父那里继承了多少条**（不是"第几条之后"）。叶子也有这个数，含义一致：`A-1` 从 `A` 继承 2 条，`A` 从根继承 4821 条。
- 暴露
  - **读取路径（打开一个节点时才有）**：
    1. 从 `sessions` 沿 `parent` 往上走，得到有序链条（根在前）；
    2. **根那一段的内容由原版提供**（原版就是那个提供者，树依赖它）：调它的加载拿事件；
    3. 每个中间节点与叶子自己的事件从 `events` 取；
    4. 拼的是**对象引用**——数组是新的，事件对象共享，不复制内容。
  - **裁剪规则**：某层自己的事件，只取到**它子节点的 `at_seq`** 为止。`A` 只取前 2 条，因为 `A-1` 就是从第 2 条之后分出去的；`A` 后来的事件不进 `A-1` 的上下文。
  - **库不做拼接**。它只回答"这条链有哪几段、每段截到第几条"（最多几十行）；拼接由运行时按清单流式做。不要用 `group_concat` 把整棵会话拼成一个字符串——那会把几十 MB 跨过数据库边界，还得再拆开。
  - **不打开就不加载**：没有任何预加载、常驻缓存。同时开多个同树叶子时若祖先被重复解析，再谈短命缓存（引用计数或 LRU），第一版不做。
- 表结构与身份
  - `PRAGMA application_id = <魔数>`：任意 sqlite 工具打开就知道"这是 treeSession 文件"。
  - `PRAGMA user_version = 1`：格式版本，迁移时先看它。
  - `meta(key, value)`：`about`（一句人话，说明这是什么、怎么读）、`tree_root`（根会话 id）、`created_at`。
  - 可选视图 `v_tree`：从首行/链条摊开父子关系，方便人肉审阅。
- 写入路径
  - **建节点**：`INSERT INTO sessions(id, parent, at_seq, plan_id, created_at)`，一条。
  - **追加事件**：`INSERT INTO events(session_id, seq, line)`，一条。用 WAL，读不阻塞写。
  - **写入幂等**：同一 `(session_id, seq)` 重复插入用 `INSERT OR IGNORE`，重放不会翻倍。
  - **顺序**：先写 `sessions` 那一行，再写它的事件；崩在中间最多留下一个"没有事件的节点"，读取时按空处理，不猜。
- 约束/许可/缺点
  - **约束**：不碰原版任何文件。`会话.jsonl.zst` 只由原版写；我们只写 `treeSession.db`。
  - **约束**：文件名不能长得像 `session.jsonl` / `session.v<N>.jsonl`（含 `.zstd` 变体），否则会被原版当成本会话的一代日志。`treeSession.db` 不沾这些模式，原版扫目录时直接忽略。
  - **许可**：`node:sqlite` 是 Node 内建的（24.18.1 实测可用，无需 flag、无需装包），所以不引第三方依赖。
  - **缺点**：库是自造格式，读它必须经本 mod；关掉 mod，这些节点就看不见了（根会话不受影响）。
  - **缺点**：sqlite 页对齐对**很多很小的树**仍有固定开销（一个空库也有几页）；树规模小的时候，这点开销可能超过收益。
- 待议
  - 节点 id 用人给的名字（`02-04-06`）还是 GUID？前者让树在磁盘上可读，后者与宿主一致、改名免费。
  - `line` 要不要按批做 zstd blob（省空间，但打开就不直接可读）。第一版明文。
  - 同一棵树被两个会话同时写（理论上不该发生）时，是用 `busy_timeout` 排队还是直接报错。

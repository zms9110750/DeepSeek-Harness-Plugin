```yaml
A 问题:
  痛点: 所有产物混在一个平铺目录里，分不清"能用的"和"试验的"，也不好回滚
  验收: 六个格子各司其职；一次提交就是一份可交付快照

  次要: 每个格子自己的清理策略
  约束: 发布里的东西必须带 README，且是给 AI 读的

  待议: 探针要不要"超过 N 天自动清"；研究要不要"只增不改"

D 实现:
  现状: 已建目录、已 git init -b main、已归类、**尚未首次提交**
```

## 1.2 删除工具

```yaml
A 问题:
  痛点: 现在没有删除能力。这一轮删文件全靠 shell，等于把不可恢复的操作藏在一个万能工具里
  验收: 删除永远进回收站；进不去就不执行，并说明原因
  适用性: 只在 Windows 桌面成立；网络盘、部分挂载点没有回收站
  先例: ZMS 的 delete 是在拟定层"记一条删除"，落盘时才真消失

B 设计:
  主要: 一个 delete 工具，永不做永久删除
  次要: 批量、dry-run 预览、还原提示
  约束: 回收站不可用 → 直接失败返回，让用户自己处理；不提供"强制删除"开关
  工具: Windows Shell API（回收站）

C 接口:
  功能: delete(paths[]) → 每项 {recycled | rejected, reason}
  暴露: 模型只看到"会进回收站"这一种语义
  待议: 能否删工作区外的东西？（倾向：允许，但失败信息更严格）

D 实现:
  首选: PowerShell 的 Microsoft.VisualBasic.FileIO.FileSystem.DeleteFile/DeleteDirectory
        + RecycleOption.SendToRecycleBin + UIOption.OnlyErrorDialogs
  细节: 先 stat 判断存在与类型；逐项处理；任何异常都算"未执行"
  魔数: 单次最多 50 项；路径 > 260 需长路径前缀
```

## 1.3 防止外部更改（快照 + 落盘校验）

```yaml
A 问题:
  痛点: ai 读 → 用户改 → ai 写，用户那份被静默覆盖。这一整轮对话里没有任何机制能发现这件事
  验收: 写之前一定有快照；落盘时发现不一致就拒绝，并给出差异；用户可二次确认放行
  适用性: 只对本地文件成立；同一进程内两个 ai 同时写仍会漏（需配合子工作区锁）
  先例: gitagent 的 partial snapshots；ZMS 的"凭据是流出来的，不是猜的"

B 设计:
  主要: 读=建快照，写=比对快照，commit=校验全部
  次要: 差异可视化、赦免通道、快照过期回收
  约束: **快照必须持久化**（用户明确要求先讨论存哪、用什么存）
  工具: sqlite（DSH 已有 session-query-sqlite）、或 .dsh/snapshots/ 下的文件

C 接口:
  功能: read 隐式记快照；write 时比对；commit(paths)
  暴露: 模型侧新增一个"落盘"动作；不一致时错误信息里带"要重读哪些"
  待议: 快照生命周期（会话级？工作区级？）、大文件怎么办、二进制怎么办

D 实现:
  关键决策: 存哪 —— 三个候选
    ① 工作区 .dsh/snapshots/*.json （跟仓走，可提交，但污染仓库）
    ② DSH_HOME/storages/snapshots （不污染仓库，但换机器丢）
    ③ sqlite（查询方便，但要引依赖）
  哈希: 内容 sha256 + mtime + size 三元组
  魔数: 单文件快照上限 8MB，超过只记哈希不存内容
```

## 1.4 压缩包工具

```yaml
A 问题:
  痛点: 想往一个 zip 里加东西、改内容，现在只能整个解开再重打；不同目录下的东西要加进去尤其麻烦
  验收: 把 zip/tar 当一个目录用 read/list/write/move/delete，最后一次 commit
  适用性: zip 可随机写；tar 只能整体重建；zstd 是流式
  先例: ZMS 已把 zip/tar/tgz/zstd 列进 read 的 target 类型

B 设计:
  主要: 压缩包 = 虚拟目录，复用 1.3 的拟定层
  次要: 嵌套压缩包、保留权限位与时间戳、压缩率选择
  约束: 大包不能整个读进内存；写操作必须先解到临时目录再重建

C 接口:
  功能: 与文件工具同形，只是 target 换成 "zip:xxx.zip"
  待议: 是否允许 tar 原地改（技术上不行，要明确拒绝）

D 实现:
  候选: yauzl + yazl（zip）、tar-stream（tar）、node:zlib（zstd 需额外库）
  细节: 先改临时副本，成功后再原子替换原文件
  魔数: 单包上限 512MB；超过则拒绝并提示
```

# 结算格式（出口锚）

> 这是**格式说明**，不是提案模板。提案的形状见 `提案格式.md`；这里定的是「一支活干完、分叉收回来时，那五句话怎么写」。

## 为什么它单独有份文件

一份提案回答"这件事该怎么做"，属于某个具体问题。汇报格式不属于任何单个问题——**每一个节点都按它收口**，每一份提案的出口都用它。所以它和 `提案格式.md` 同级，放在 `计划/` 根上，被提案引用，而不是被提案定义。

两个锚对应两份格式：

| 锚 | 位置 | 文件 |
|---|---|---|
| 入口锚（提案） | 分叉那一刻：要做什么、什么算完、先去哪 | `提案格式.md` |
| 出口锚（结算） | 分叉收回来那一刻：结论、证据、产物、坑、去哪查 | 本文件 |

## 六行，缺一不可

子会话收工时的最后一条消息，必须是这六行（其余内容不算）：

```
verdict: success | reject | shelved
conclusion: 做了什么，或没做成什么。一句话，动宾结构。
evidence: 怎么确认的。命令与读数、文件路径与行号、接口签名。
artifacts: 改了什么、新增了什么，逐条列路径。
pitfalls: 试过但不成立的那条路，一句话，防止下一个再试。
where: 要细节回哪个节点、哪个文件。
```

`verdict` 是这一支自己的判断，不是请求：`success` 成立、`reject` 不成立（该层计数 +1）、`shelved` 先搁下（不计数）。少任何一行，解析就不通过——**这一支不算结算完成**，节点保持 open，等父手工 `plan_file`。

## 五项各自的写法

1. **结论**：做了什么，或没做成什么。一句话，动宾结构。不要写"已完成调研"这种没有宾语的。
2. **证据**：怎么确认的。命令与读数、文件路径与行号、接口签名。**这一项是给别人复核用的**，不是给自己交差的。
3. **产物**：改了什么、新增了什么，逐条列路径。没有产物就写"无"，不要省。
4. **坑**：试过但不成立的那条路，一句话。**这项最贵**——树简报会把失败与搁置的坑原样带出来，下一个照着避。
5. **去哪查**：要细节回哪个节点、哪个文件。父的上下文里只留这五行，原文在子会话里。

## 合格与不合格

不合格（四句话都说完了，但没有一项可复核）：

```
完成了树上下文的调研，方案已确定。
```

合格：

```
verdict: success
conclusion: 节点用 session.fork(atSeq)，不用子 agent 的 fork 后端。
evidence: dsh-subagent-fork-in-process/README.zh.md:113 写明 prepareContinuable() 只返回已完成轮次；
          atSeq 是 dsh-api-session-controller fork 请求的精确端点，README.zh.md:63。
artifacts: 计划/13-树上下文工程/B-02.md（新增）；13/README.md（改 3 处）。
pitfalls: spawn 后端能省掉整段前缀，但前缀一变缓存全失效，别为省 token 换回去。
where: 13/B-02 与子会话 session-<uuid>。
```

## 谁来写，谁去读

- **写**：干这段活的那个会话自己写。写完立刻回到父，父不重读过程。
- **读**：父只读五项；`plan_tree` 把 `pitfalls` 带出来给所有人看；细节靠 `where` 回查。
- **失败兜底**：子没按六行回报，就不自动归档，节点留 open，父用 `plan_file` 手工补——宁可留个 open，也不要凭空造一份结算。

## 与"主题"的关系

不派发任何任务的纯对话段**没有**这五项（它没有产物），它只有一行主题。主题是压缩的锚，不是结算的替代品。

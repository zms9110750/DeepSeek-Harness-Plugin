# 设计

## 这个问题背后是什么

表面上要的是"分目录"，真正要的是三件事：

1. **可回退** —— 让我能回到某个已知好的状态
2. **可交付** —— 哪些东西是"能用的"，要有个说法，而不是靠记忆
3. **责任边界** —— 哪些可以随便删，哪些不能

## 牵连着什么

- git 是"可回退"的唯一现实手段，所以目录设计必须配合提交粒度
- "发布要有 README"不是文档问题，是**交付契约**：别人（包括另一个 ai）拿到它，不看源码也知道怎么用
- "探针可以删"意味着这个目录里的东西可以随时清空，那它就不能存放任何被引用的东西

## 要不要顺带做别的

应该顺带定下**清理规则**：探针目录的自动过期、研究目录只增不改。否则半年后又是一团。

## 放在架构哪一层

不属于插件系统。这是**工作区约定**，靠 README 和 git 约束，不靠代码。

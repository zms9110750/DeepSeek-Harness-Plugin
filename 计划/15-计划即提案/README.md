## 两份 B 为什么都采纳

它们回答的不是同一个问题，可以分开否，所以分开立：

- B-01 管**能不能派**：层序、类型、计数、闸门
- B-02 管**派出去怎么收口**：入口锚、出口锚、摘要

单拎任一条都跑不通：只有 B-01，派出去的活没人结账；只有 B-02，谁都能派。

## 已经钉死的

1. 计数按层分开，层是并存的；B 连否两次仍然派 B，执行中的 B 派出的 C 是另一层。
2. 未派发、搁置都不计数，也不打断连续。
3. 研究不是层，是类型；没有层序，所以层规则对它不适用而不是开例外。
4. 探针只能开在研究里，继承研究的判据。
5. 研究只能派研究，堵住绕开闸门的后门。
6. 研究任务挂在第 3 次被否决的那个派发任务之后。
7. 采纳 = 写事件 = 分叉点；父当下只知道"某份被采纳了"，结算很久以后才回来。
8. 只读的判据是**"有没有子工作区"**，不是"有没有第一个计划"（B-05 更正了 A-6 的落地形式）；完全权限下跳过整套，但用户仍可主动开锚点。
9. 出口锚五项必填：结论、证据、产物、坑、去哪查。

## 实现的硬规则

前四条是两次事故换来的（会话打不开、重启无效）；后四条关于清理，一条都不能省。

1. **插件自有事件必须走 `appendPluginRecord`**：它强制 `plugin:` 命名空间并标 `ignorable:true`。
2. **不要用 `session.append` 写自定义类型**：写出的是"未知且不可忽略"，加载器会**拒绝解释整份日志**。
3. **不要凭空造面事件类型**：`system/message`、`developer/message`、`assistant/message`、`tool/result` 都是步骤内事件；`user/message` 是唯一不受约束的。
4. **一种事件带 `op`**，不一个动作一个类型。
5. **只通过 fiber 绑定的注册面注册**：`tools.register` / `tools.guard` / `commands.register` / `sessionProjections.register` / `ctx.provide` 都走 `ctx.effect`，disposer 挂在调用方 fiber；客户端 `sidebarRightTabs.register` 要自己包 `ctx.effect`。自己 new 的数组、监听、定时器必须自己收。
6. **会话级活状态放 `apply()` 里**，不放模块顶层——模块顶层会被下一次启用继承（"已放开"曾经就这么漏过一次）。
7. **任何异步续体都要有 disposed 闸门**：`ctx.effect(() => () => { disposed = true })`，醒来先看它。`whenIdle().then(...)` 在 fiber 死后仍会醒，会往日志里写记录。
8. **卸载后不要把死 ctx 留在闭包里给界面用**：客户端 `runtime` 卸载时置空，页面宁可报错。

## C系列-接口（C-01-01）· 派发、闸门与树

- 功能
  - 节点两种类型：**计划**与**研究**。计划带层序（模板里的第几位），研究不带层序。
  - 模板只声明一条有序层名，长度任意（1 层到 N 层）。闸门只比较序数，不认层数。
  - 派发前做三项检查，任一不通过就当场拒绝，把原因作为工具错误原文返回：
    1. 目标层在模板里存在；
    2. 目标层序 > 当前层序；等深只有模板声明"该层可递归"才放行；
    3. 该层计数 < 3。
  - 计数：每层一个数，等于**自上次成功以来的否决数**。否决 +1，成功归零；搁置与未派发都不动它。
  - 研究只能派研究。研究没有层序，所以第 2 项检查对它不适用，不是给它开例外。
- 暴露
  - 用户看到的样子：
    - 树上每个节点一行：标题 / 类型 / 状态 / 父 / 派发理由 / 结算理由。不显示正文。
    - 某一层计数到 3，该层出现一条提示"需要研究任务"；此后该层的计划派发被拒绝，直到研究任务结算。
    - 只读状态与当前可写范围显示在输入框旁。
  - 模型看到的样子：
    - `task_dispatch`：参数为父节点、类型、目标层（研究时省略）、工作区、派发理由（一句话）。
    - `tree_report`：参数为可选的节点 id；返回树的形状，加每个节点的两句——派发理由、结算理由。
  - 基准：一切以节点为基准。工作区在派发那一刻写死，子任务不能改。
- 待议（已决）
  - 层序**从 0 编号**：`layerIndex = 层在模板里的下标`，比较只用它。
  - "可递归"用**层名列表**（空表 = 全禁），比布尔精确：只放开写明的那几层。
  - 计数阈值 3 **写死**在插件里（`MAX_REJECTIONS`），进配置等有人真的要改再说。
  - 仍未决：节点 id 要不要带层前缀（现在是 `n1`、`n2` 一条线性序列）。

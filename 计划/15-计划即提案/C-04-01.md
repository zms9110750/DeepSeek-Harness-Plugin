## C系列-接口（C-04-01）· 计划的记录与投影

- 功能
  - 一份计划 = 一条 `plugin:plan-tree/node` 记录，`op:'plan'`，正文在 `body`。写入只走 `appendPluginRecord`（可忽略）。
  - 一条记录的生命周期由 `op` 推进：`plan`（草案）→ `adopt`（计划）→ `dispatch`（进行中）→ `file`（完成/失败/搁置）；`reject-draft`、`shelve-draft` 停在"搁置草案"。
  - 记录不可变：任何状态变化都是**新的一条事件**，不是改旧记录。所以"看过的那份计划"永远查得到。
- 暴露
  - 投影 `plans`（wire 给客户端）：
    ```
    { plans: { [pN]: { id, title, body, type, layer, layerIndex, templatePath,
                       topic, goal, done_when, where_to_learn,
                       author: 'model'|'user', createdAt, parentSession,
                       adopted: bool, rejected?: bool, shelved?: bool,
                       path?: string        // 仅 0.15.x 及更早的记录有
                     } },
      planSeq: number }
    ```
  - 工具 `plan_write(title, goal, done_when, where_to_learn, body?, type?, layer?, template?) → { id }`：只记，不派发、不落盘。
  - 工具 `plan_export(plan, path, overwrite?) → { path, bytes }`：唯一的出口。相对路径按会话工作目录解析，缺扩展名补 `.md`，已存在则拒绝（除非 `overwrite: true`）；因为它是工具，写锁照常生效。老记录（只有 `path`）会把文件读回来再导出。
  - 命令：
    - `/plan-adopt <id|路径>`、`/plan-reject <id|路径>`、`/plan-shelve <id|路径>`：用户对草案的决定；按 id 优先，老记录认路径。
    - `/plan-new <json>`：面板新建，`{title, layer, body}`，与 `plan_write` 同一条写路径（`author:'user'`）。
  - 基准：**以记录为基准**。文件是历史遗留（`path` 字段），只有老记录还会有。
- 待议
  - （已决）导出用 `plan_export` 工具，不做命令别名：多一个入口就多一个要单独维护的权限面。
  - 正文长度上限：几千字的计划要不要拒绝，还是照收（现在照收）。
  - 老记录的兼容什么时候能停：`path` 与"按路径采纳"现在都还在。
  - `planSeq` 只增不减：删掉（否决）的计划也占号，id 不复用——这是有意的，别改成复用。

# B-05 模板进配置

- 类型：plan
- 层：（未指定）
- 目的：让计划的层序可配置，替换写死的 A/B/C/D
- 判据：LAYERS 从源码常量变成配置项；改配置后层名校验跟着变；现有测试仍通过
- 去处：发布/plan-tree/index.js 里的 LAYERS / RECURSIVE 常量；cordis 插件 Config 的写法见 dsh-plan-mode 的 Config

## 正文

## 做法

模板是一份配置，放在插件配置里（`cordis.patch.yml` 的 `config`）：

```
layers: [A, B, C, D]
recursive: []
maxRejections: 3
```

插件在 `apply` 时读一次，之后不再变。同一台机器上所有会话共用一套层。

## 优点

- 零解析成本：不需要从计划文件里读模板。
- 闸门逻辑不变，只是把常量换成配置项。

## 缺点

- 一个 profile 只有一套层。写小说和写代码要换模板，得改配置、重载插件。
- 混用要手动切，和"一个计划里可以混模板"冲突。

## 判据

改完 `LAYERS` 不再出现在插件源码里；把配置改成 `[设定, 大纲, 章节]` 后，`plan_dispatch` 接受 `章节`、拒绝 `D`。

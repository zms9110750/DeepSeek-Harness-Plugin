## C系列-接口（C-05-01）· 子工作区与读写锁

- 功能
  - **认领**：一条 `op:'claim'` 记录，`{ path, planId, by, at }`。`op:'release'` 撤回。路径归一化（统一 `\`、去尾斜杠、Windows 不分大小写）之后作键。
  - **归属判定**：路径 `P` 属于认领 `C`，当且仅当 `P == C` 或 `P` 以 `C + 分隔符` 开头。按目录边界比，不按字符串前缀（`/a` 不是 `/ab` 的父目录）。
  - **可写判据**（守卫 `tools.guard`）依次是：
    1. 不是写工具（`write/edit/pwsh/bash/delete`）→ 不管；
    2. 会话被 `/plan-tree off` 放开 → 不管；
    3. 权限档是 `danger-full-access`，或读不到权限 → 不管；
    4. 一条认领都没有 → 不管（不做收窄：锁的职责是别让两支写同一块地方，不是给新会话上枷锁）；
    5. 工具参数里看不出目标路径（如 `pwsh`）→ 拒绝；
    6. 目标路径不在任何认领内 → 拒绝，并列出可写范围。
  - **继承**：子会话分叉父的日志，所以它看得见**整条祖先链**的认领；认领不需要逐层复制。
- 暴露
  - 投影 `subWorkspaces`（wire 给客户端）：
    ```
    { claims: { [归一化路径]: { path, planId: string|null, by: sessionId, at: number } } }
    ```
  - 服务 `subWorkspaces`：`claim(agent, path, planId?)`、`release(agent, path)`、`owns(state, path)`、`claimFor(state, path)`、`claimsOf(state)`、`rootOf(agent)`、`stateOf(agent)`。
  - 命令 `/sub-workspace list | add <绝对路径> | remove <路径>`：给**用户**用的手动入口。
  - `plan_dispatch(…, workspace)` 会自动认领；**认领事件写在分叉边界之前**，子因此看得见自己的写范围。
  - 用户看到的样子：锁生效时写工具被拒，拒绝文案里带一条逃生口（`/plan-tree off`）。
  - 模型看到的样子：没有新工具。它只会在写被拒时读到原因。
- 待议
  - （已决）**读范围不做**：读只看会话工作区，不授权、不记录（见 B-05）。子工作区只限写。
  - `/sub-workspace add` 要不要也能由模型调（现在只有用户能敲）。
  - 认领要不要过期，或随节点结算自动释放（现在只增不减，靠 `/sub-workspace remove`）。
  - 认领与自己根目录的关系：认领在根之外时（读得到、写不进），要不要提示。

## B系列-设计（B-01-01）· 把会话变成一棵可寻址的树

- 主要目标
  - **先有锚。** 每个话题/节点有一对日志事件：入口（`op: plan`，四项：主题、做什么、什么算完、先去哪）与出口（`op: file`，五项：结论、证据、产物、坑、去哪查，另加 `verdict`）。两条都是消息：入口进子会话第一条，出口回传给父。锚的事件序号就是分叉边界——这也是它必须落日志、不能是旁表一行的原因。
  - **裁得掉。** 折叠用 surface replace（`{op:'replace', startSeq, endSeq}` + `sourceEventSeqs`）把一段可见面遮掉、摘要替位，日志留原文。记账强制：区间内漏列任一可见节点直接报错，不静默修正。不给模型新工具——折叠是调度行为，不是模型随手可用的动作。
  - **派得出去。** 边界自取“最后一条事件（含）”，不用产品自带的“最后一个已完成轮次”（进行中的这一轮会被排除，刚写的计划 fork 出去看不到）。种子过一道 JSON 往返；预设与 `agentOptions` 显式给；拼种子时滤掉 `source.kind='runtime-context'` 并重编号。
  - **存得住。** 树库用 `node:sqlite` 两表：`sessions`（谁从第几条接上）、`records`（提案记录）。只记关系不记消息；一棵树一个文件，与消息树共用一个连接，避免 WAL 冲突。
  - **联得上。** 成员走 `agentTeams.sendMessage`；树节点不在花名册、没有 `target`，走 `agent.followup`。没有群发，通知 N 个就发 N 次；一律 `append`，不唤醒。
  - **收得回。** 九态（借 A2A `TaskState`）+ 结算六行；终结态不可重启；“采用”只能用户写，“完成”由执行事实推导；连败按模板累计，到 3 / 6 / 9 建 F 复盘并强制转研究，上一份未交付则不新建。
  - **看得见。** 往下继承、往上只收结论（父不该看见孙）；客户端只读 `sessionProjections`，不直连 sqlite；详情按需拉取，一次一份。
- 次要目标
  - 折叠记录与锚是同一份数据的两面，不必各记一份。
  - 节点结算就是计划的执行日志，计划本身不必另写完成记录。
  - 树库是可搬走的归档单元：删、拷、打包都以一棵树为单位。
  - 公共面板直接复用宿主团队面板（读领队会话的 `agentTeam` 投影），省掉一整套 UI。
  - 坑的集合是这一层的知识，研究节点直接拿它当输入。
- 约束/许可/缺点
  - **约束**：不改内核、不改会话日志格式、原版会话一个字节都不碰；所有机制绕在宿主外面，靠插件 API 接。
  - **约束**：折叠只重组可见面，不改日志；不得让两个分支看到同一段前缀的不同内容。
  - **约束**：子工作区必须落在会话 cwd 之内，越界认领直接拒绝；并发合并靠 git。
  - **约束**：子会话必须带完整工具集（预设 + `setup` 同时给），否则连读文件都做不到。
  - **约束**：计划不是文件，只存在于会话日志与树库，需要文档时显式导出。
  - **许可**：树库缺失或写失败时派发照常完成，只告警——会话先建成比记账完整更重要。
  - **许可**：状态广播失败只告警，不影响记录本身。
  - **缺点**：缓存按前缀算，折叠只能尽量落在话题边界；切在句子或工具调用中间，该点之后全部失效。
  - **缺点**：折叠点必须与分叉点对齐，否则兄弟前缀差一个字，共享缓存全废。
  - **缺点**：成员只进不出（无逐出、名字永久、上限每条会话 8 / 16），树节点也进不了花名册——两套身份暂时不统一。
  - **缺点**：不能用“等待”做同步——三方同时等会成环，实测死锁过一次。
  - **缺点**：磁盘仍是复制，实测父 9.8 MB → 子 5.1 MB；省磁盘要另立提案。
- 被否决的替代
  1. **摘要压缩长历史**：省 token，但不可寻址——压完不知道哪句属于哪个话题，也派不出去、结算不了。撤掉。
  2. **只给引用、请求组装时再拼**：磁盘真正不翻倍，但要动持久化层、失败面大；留作后续提案，本份先做复制前缀。
  3. **用 `wait_agent` 做同步**：会成环，实测死锁过一次，不用。
- 工具
  - `appendPluginRecord`（唯一写自有事件的口子，一个动作一个 `op`，幂等可回放）、`sessionProjections`（簿记，不进模型上下文）。
  - surface replace + `sourceEventSeqs`（`@deepseek-ai/dsh-session`）——折叠。
  - `ctx.agents.create({ sessionId, parentAgent, meta, seed, inheritedEventCount, agentOptions, setup })` + `buildForkSeed(events, boundary)`（`@deepseek-ai/dsh-session/fork`）——派发。
  - `ctx.subagents.registerProvider(...)`——把上下文来源收成可替换的 `tree-fork`，换来源只改这一个函数。
  - `node:sqlite` + `treeSessions`——树库。
  - `ctx.agentTeams.sendMessage / listMembers / spawnTeammate` 与 `agent.followup(createUserMessage(...))`——两条通道。
  - `team_task_*`——公共板；承担展示与共同记忆，不承担状态语义。
  - `plan_write / plan_tree / plan_show / plan_file / plan_status / plan_dispatch`——计划的纸面、索引、结算与派发。
  - 会话日志 `session.v4.jsonl.zstd`——原文来源，也是回查入口。
- 外链（本机解包目录 `探针/asar/out/dsh/node_modules/@deepseek-ai/` 下，随时可重解）

  - `dsh-subagent/README.zh.md:113`——本地提供方只有 `prepareContinuable()`；fork 返回已完成轮次，切点到此为止。
- 结论：**采纳**。七面里锚是承重的：先落锚，其余六面围着它长。

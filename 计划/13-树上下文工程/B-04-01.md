# 从最后一个事件处真分叉，并把前缀压力挡在树库里

## 实际问题

- [用户] 派活给子 AI 时只有两个坏选择：全给它，或什么都不给。
- [ai推断] 产品自带的 fork 只复制到最后一个 `turn/end`（含），进行中的这一轮被排除，所以刚写的计划、刚说的话，fork 出去的成员看不到。
- [ai推断] 分叉在磁盘上是一份真副本，实测父 9.8 MB → 子 5.1 MB。
- [用户] 用户要求：会话的存储要能解决这个压力。

## 需要考虑的问题

- [ai推断] 边界要自己定：走 `agents.create({ seed, inheritedEventCount })`，边界取"最后一条事件（含）"。
- [ai推断] 逐字前缀才有缓存价值：兄弟分支起点相同才共享缓存，差一个字从第一个 token 起就命中不了。
- [ai推断] 种子要过一道 JSON 往返，否则活事件对象的类实例会让转发失败，且失败是半成功。
- [ai推断] 预设与模型必须显式给：不给预设子会话只剩几个工具，不给 `agentOptions` 系统提示词里的 `{{model}}` 取不到值。
- [ai推断] 磁盘是复制、内存是共享；想省磁盘只能"只给引用、请求组装时再拼"，那要动持久化层。
- [ai推断] 树的形状要独立记账：一棵树一个 sqlite 文件，记关系与提案记录，不记消息。

## 非目标

- [ai推断] 不做增量压缩与差分存储。
- [ai推断] 不做跨机器/跨进程的上下文迁移。
- [用户] 不修改原版会话文件，一个字节都不碰。

## 次要目标

- [ai推断] 树库天然是可搬走的归档单元：删、拷、打包都以一棵树为单位。

## 约束

- [用户] 不动原版会话日志。
- [ai推断] 树库只写自己的文件，文件名不能长得像 `session.v<N>.jsonl`。
- [ai推断] 子会话必须带完整工具集（预设 + setup 同时给），否则连读文件都做不到。

## 工具

- [ai推断] `ctx.agents.create({ sessionId, parentAgent, meta, seed, inheritedEventCount, agentOptions, setup })`。
- [ai推断] `buildForkSeed(events, boundary)`（`@deepseek-ai/dsh-session/fork`）。
- [ai推断] `ctx.subagents.registerProvider(...)`：把上下文从哪来收成一个可替换的 provider（`tree-fork`），A→B 只改一个函数。
- [ai推断] `node:sqlite` + `treeSessions`：树库，`sessions` / `records` 两表。

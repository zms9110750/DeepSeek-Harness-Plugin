# 扳机与实现

### 计划模式

- 计划模式 = 只许写已声明的子工作区；没有声明任何子工作区时，写工具一律拒绝（包括 `pwsh` 与 `plan_export`）。普通模式保持原行为（无认领放行、有认领限内）。
- 在用户提出具体命令后，ai需要根据任务选择一个提案模板填写并给用户采纳

- 写出来的提案是提案草稿。用户可以编辑，甚至自己创建。
- 提案草稿会列出和可筛选。否决的草稿进入归档不再列出，但可以进行查询。

- 采纳的提案，状态变为采纳。
- 用户发出命令，执行提案。ai使用工具，输入提案的id作为参数，进行派发
- 派发是一次工具调用，在派发出来后，立刻返回，告知派发成功，以及当前的任务树状态。


### 派发任务

- 当一个任务进行派发以后，从此处fork会话，并拼接“你是被派发执行xx提案的子任务ai。提案的具体内容为xx”
- 从这里继续和进行并发。
- 可以通过一个工具，查看当前的树架构，或者一个节点的详细描述。

- 当一个任务的状态变化时，系统自动通知他的父兄子节点。
- 任务状态有[进行中，搁置（因为用户改变主意而不执行。和代价比较大可能需要别的方式，让父ai或用户进行授权），需要研究，失败，交付]
- 当一个父级有三个从同样的模板创建的任务失败后，禁止这个模板创建计划，返回提示需要使用研究任务。

### 储存

- 任务是一个树结构，没有具体的层级要求。例如，开发者实现里面的需要研究，界面接口的待议，可能会再产出一个新的A系列的提案递归下去。
- 使用sqlite储存这个任务板。在表里面描述这个任务的父级。以供在内存里重构树
- 使用表储存消息会话。每一个消息会话表都要对应一个任务。
- 一个任务的行，还需要描述，派发时，这个任务是从父任务的消息的哪一行进行分支的。在内存后也不拼接完整，仅在发送时进行拼接
- 任务树需要有一个公共板。允许所有任务查看。

### 并发
- 当一个子任务派发时，创建一个属于其的工作空间。
- 这个空间使用硬链接的方式复制源。并设置权限为只读
- 这些相同的文件允许ai查看和了解。但是要执行更改，需要使用工具对路径进行解锁。解锁的部分会移除硬连接，然后直接复制原始文件。
- 最后通过git进行合并。使用这个技术必须是git仓库的文件夹。

### 子工作区

- ai可以使用工具，为自己决定子工作区。只能写子工作区里的文件。可以查看原始工作区的范围。
- 额外工作区：ai可以使用工具请求用户，申请一个临时工作区，仅在会话里有效，并且用户可以从ui里把这个目录随时移除
- 由于并发需要一个git，所以可以将子工作区定在有git的文件夹里。使用派发为并发时，自动修改子工作区路径。

### ai对话

- 一个会话下的多个任务之间可以沟通，但仅限于父子，和兄弟，这样的直系节点。
- 这些节点使用官方提供的团队机制。节点需要有id，通过id指定告知对象。
- 任务的进行中可以和附近节点对话。任务的搁置与完成和失败，需要提供摘要。对于类似于项目风格之类的需要记录的东西，写在通用板里面。

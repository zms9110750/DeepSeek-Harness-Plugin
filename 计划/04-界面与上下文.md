## 4.1 聊天侧边栏

```yaml
A 问题:
  痛点: 有些对话不该进消息列表（"环境的英文是什么"这种一问一答），但也不想切窗口去官网
  验收: 侧边栏一个入口，点开就是 DeepSeek 官网聊天，用用户自己的登录态
  适用性: 需要页面能嵌第三方站点；需要用户已登录；离线不可用
  先例: 参考图里那个产品左侧就有一列功能面板；DSH 自己也有 ui-sidebar-browser

B 设计:
  主要: 复用内嵌浏览器面板，指向 chat.deepseek.com
  次要: 快捷键唤起、记住上次会话、和主对话互不干扰
  约束: 不做消息抓取（不读它的 DOM）；不代替用户登录；不把内容送进主上下文
  工具: @deepseek-ai/dsh-client-ui-sidebar-browser（已装且启用）

C 接口:
  功能: 侧边栏图标 → 面板 → 嵌入页
  暴露: 用户可见的一个入口；模型完全看不见
  待议: 登录态是独立 profile 还是共享？独立更安全，但要重新登录一次

D 实现:
  现成件: 那个 browser 面板已经存在，问题只是"加一个默认 URL 的入口"
  难点: 第三方站点可能拒绝被 iframe/嵌入（X-Frame-Options），需要看 DSH 用的是 webview 还是 iframe
  魔数: 无
```

**判断**：这是所有需求里**最便宜**的一个。如果 browser 面板用的是真正的 webview，那基本就是加一个书签。

## 4.2 树上下文工程

（设计细节见 `03-协作调度.md` 的 3.4，这里只记界面部分。）

```yaml
A 问题:
  痛点: 树只有模型看得见，用户看不见，等于黑箱
  验收: 用户能看到任务树，能点进任意节点看它的消息
  适用性: 依赖 3.4 的 projection
  先例: 无

B 设计:
  主要: 一个树视图，节点带状态（open/completed/failed/interrupted）
  次要: 点节点跳转消息、折叠、失败链高亮
  约束: 只读视图，不在 UI 上改树（改树只能通过工具）
  工具: Client 插槽（settings.section 或 sidebar.panellist 开一个面板）

C 接口:
  功能: 树的只读渲染 + 节点详情
  待议: 放侧边栏还是放主区；和 4.1 抢不抢位置

D 实现:
  数据来源: projection 的 view（tree-context 已经写了 wire.viewSchema/view）
  注意: 客户端插件是即时生效的，改 UI 不用重启 —— 比改宿主侧舒服得多
```

---

## 附：三条界面层面的既有结论

1. **客户端插件即时生效**，宿主插件要重启 —— 所以凡是"能只改 UI"的，优先只改 UI。
2. **插槽是加法的**：`shell.overlay` 明确写着"新 id 加在旁边，不替换已有条目"。想加东西不需要动别人的代码。
3. **主题变量必须用**：`--dsw-alias-bg-layer-1`、`--dsw-alias-label-primary`、`--dsw-alias-brand-primary` 这一套，明暗两套值都有，硬编码颜色会在另一主题下坏掉。

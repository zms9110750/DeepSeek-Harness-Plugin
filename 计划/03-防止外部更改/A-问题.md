## A系列-问题

- 痛点/验收
  - 模型读文件 → 用户改文件 → 模型写文件，用户那份被静默覆盖，全程没人发现。
  - 做到"写之前有快照、落盘时校验、不一致就拦下并给出差异、用户可二次确认放行"才算满意。
- 适用性
  - 基于"用户会在模型会话之外改文件"才成立；若工作区只有模型在写，这层就是纯开销。
  - 如果工作区本身在版本控制下且用户频繁提交，用 git 兜底可能比自建快照更省事，本提案的价值会下降。
- 先例
  - gitagent 的 partial snapshots；ZMS 用"凭据"表达"你读过它"，落盘前必须持有。
  - 凭据模型可抄；存储方案要看本机条件，不能照搬。

# 设计

## 这个问题背后是什么

接 MCP 不是"多几个工具"，它同时动了三件事：

1. **模型看到的工具表** —— 每加一个 server 就加一批工具
2. **进程** —— stdio 型 server 要起子进程
3. **权限** —— 外部工具的风险等级和我们自己的工具不一样

## 牵连着什么

- 工具表一变，prompt 前缀就变，KV 缓存全废。这是钱的问题，不是洁癖
- 起进程要过沙箱和授权，不能"启动即连接"
- 外部工具的四个描述符（写／破坏／幂等／外部）正好是权限系统（06）的输入

## 要不要顺带做别的

要。**一个稳定代理**比"每个工具注册一个"重要得多：
工具表不变，才能长期开着 MCP 而不烧缓存。

## 放在架构哪一层

宿主侧：连接管理 + schema 缓存 + 工具名单；模型侧只看见一个代理工具。

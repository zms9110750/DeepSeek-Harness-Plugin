# 设计（否决）

## 方案是什么

每个 MCP 工具注册成一个 DSH 工具，名字如 `mcp__github__issue_create`。
模型看到的工具表就是全部外部工具的并集。

## 当时的理由

最直观：模型像用自己的工具一样用外部工具，不需要中间层，也不需要学习代理协议。

## 为什么被否决

两条硬伤：

1. **工具表随 MCP 清单变化** —— 装一个 server 就改一次工具表，prompt 前缀变，KV 缓存全废，成本直接体现在账单上
2. **权限粒度错位** —— 外部工具和内建工具混在同一张表里，"按 server 整体禁用"变成要维护一堆名字

对照实现（Reasonix）用的是稳定代理，且明确写了理由是"不改变模型可见的 schema"。

## 留下的教训

"模型能直接看见"是体验，不是架构。体验可以由一个代理工具提供，架构必须保持稳定。
